# 行情数据拉取规范（铁纪律）

> **生效日期**：2026-08-20  
> **背景**：历史回填过程中对 baostock **高并发、反复 login**，导致账号被永久封禁。此后所有拉数行为必须遵守本文，**禁止**再触发接口恶意请求。

---

## 一、总原则

| 原则 | 说明 |
|------|------|
| **登录一次，全程复用** | 同一进程内 `bs.login()` **最多 1 次**，后续所有 query 共用该会话 |
| **禁止高并发 login** | 多线程/多进程各自 login = 必封；并行度 >1 时必须先确认无 login |
| **日常与回填隔离** | 每日产出（stock/slow/up + 15:05 收盘补全）**不得**与历史回填同时跑 |
| **baostock 非必需** | 日线/分钟线/交易日历均有 akshare / 新浪 / 腾讯兜底，baostock 仅作备用 |
| **慢速补数** | 历史数据从 **2026-08-21 起** 按日/按月慢慢补，**禁止**一次性批量跑全年 |
| **先停后查** | 发现 login 失败、黑名单、频繁请求提示 → **立即停止**，不要重试 login |

## 二、数据源优先级（代码已实现，禁止随意改序）

### 2.1 每日产出（`daily_close_job.py` / `price_service.py`）

| 数据类型 | 优先 | 备用 1 | 备用 2 |
|----------|------|--------|--------|
| 交易日历 | 本地法定节假日表 `fetch_calendar` | 新浪 `tool_trade_date_hist_sina` | baostock |
| 日线 OHLC | 腾讯 `stock_zh_a_hist_tx` | baostock | 东财 `stock_zh_a_hist` |
| 9:35 / 13:15 分钟价 | baostock 5 分钟柱 | 新浪 1 分钟 | 无（缺失即留空） |
| 当日实时 | 新浪 hq.sinajs.cn | — | — |

> **交易日历已改为本地优先**（2026-10-09）：新浪 `tool_trade_date_hist_sina` 依赖 `py_mini_racer`，其在 Apple Silicon（arm64）上因 x86_64 dylib 架构不兼容会反复报 `dlopen` 错误。`price_service.get_trade_calendar` 现先走本地 `fetch_calendar`（含法定节假日），仅当其失败才回退新浪/baostock。

**日常 cron 必须设置** `DISABLE_BAOSTOCK=1`（见 `scripts/daily_close_cron_entry.sh`），避免收盘补全误触 baostock login。

### 2.1.1 买入价 / 卖出价口径（与首板 IRON_RULES 一致）

| 字段 | 合法值 | 禁止 |
|------|--------|------|
| `buy_price` | **D1 开盘价** `get_open_price(code, D1)` | D0 开盘价、D0 收盘价、9:25 前新浪今开 |
| `sell_price_935` | **卖出日 09:35 分钟价** | 日线开盘价冒充 |
| `sell_price_1315` | **卖出日 13:15 分钟价** | 日线收盘价冒充 |

- 早盘 / `stock.py` 同步：**只写** code/name/rank，`auto_enrich=False`
- 15:00 收盘补全：**强制**用 D1 开盘价覆盖当日买入价；卖出日强制重拉真 9:35/13:15
- 新浪当日 OHLC 兜底：**9:25 前返回 None**，禁止写买入价
- `get_minute_price`：**禁止**开盘/收盘兜底；分钟缺失返回 None

### 2.2 历史回填（`backfill_*.py` / `historical_pool.py`）

| 数据类型 | 优先 | 禁止 |
|----------|------|------|
| 涨停池 / 首板 | 同花顺首板池 | 东财历史池（不稳定） |
| 日 K | 腾讯 / 东财（`price_service._fetch_daily`） | baostock 全市场扫描 |
| 补价 enrich | `price_service`（同上优先级） | 多进程各自 login |

**历史回填默认 `--source tx` 或 `ths`，禁止 `--source baostock`。**

## 三、baostock 使用规范

### 3.1 何时可以用

- 仅当腾讯/东财/新浪**全部失败**且已有**未被封**的测试账号
- 单次任务、单进程、login **1 次**后连续 query
- 必须在非交易时段、非 daily cron 窗口外手动执行

### 3.2 何时禁止

- ❌ 历史回填默认流程
- ❌ `--workers > 1` 且任务内含 login（`backfill_stock_year.py --source baostock` 已废弃）
- ❌ UI 进程与回填脚本**同时**跑 baostock
- ❌ login 失败后循环重试
- ❌ 用日常 PushPlus / 通知所用机器 IP 做 bulk 扫描

### 3.3 账号策略

- 原账号已永久封禁，**换号仅用于 isolated 测试**，不可用于 bulk
- 测试前：`export DISABLE_BAOSTOCK=0` 且确认无其他进程占用
- 测试后：`export DISABLE_BAOSTOCK=1`，`bs.logout()`（若曾 login）

### 3.4 代码层保障（`price_service.py`）

- `_BS_LOCK` + `_BS_LOGGED_IN`：进程内单例 login
- 黑名单/频繁 login 错误 → `_disable_baostock()`，本进程内不再 login
- 环境变量 `DISABLE_BAOSTOCK=1` → 启动即禁用

## 四、历史回填执行规范

### 4.1 暂停开关

文件：`01_量化模型/首板战法/每日交易记录/data/BACKFILL_PAUSED`

- **存在该文件** → 所有 `backfill_*.py` 拒绝启动
- 恢复回填前：阅读本文 → 确认无 cron/无 UI 补数 → **删除该文件** → 再跑

### 4.2 推荐节奏（2025 年补数计划）

```
阶段 1（当前暂停）：stock 2025 部分月份已有数据，余下月份待补
阶段 2：stock 2025 全部完成
阶段 3：slow 2025
阶段 4：up 2025（必须在 stock+slow 完成后）
```

**单日上限建议**：

| 操作 | 上限 |
|------|------|
| 回填交易日 | ≤ 5 天/次 |
| enrich 补价 | ≤ 20 笔/次 |
| 请求间隔 | ≥ 0.3s/股（腾讯/东财），≥ 1s/股（baostock 若启用） |
| 每日总回填时长 | ≤ 30 分钟 |

### 4.3 标准命令（恢复后）

```bash
cd 01_量化模型/首板战法/每日交易记录
export DISABLE_BAOSTOCK=1   # 铁纪律：回填默认禁用 baostock

# stock 单个月份
python3 ../stock/scripts/backfill_stock_year.py \
  --year 2025 --months 2025-03 --source tx --records-only

# 补价（小批量）
python3 ../stock/scripts/backfill_stock_year.py \
  --year 2025 --months 2025-03 --enrich-only
```

### 4.4 禁止命令示例

```bash
# ❌ 禁止：baostock 全市场 + 多 worker
python3 backfill_stock_year.py --year 2025 --source baostock --workers 6

# ❌ 禁止：全年一次跑完
python3 backfill_stock_year.py --year 2025 --commit --enrich

# ❌ 禁止：回填与 UI「强制重拉」同时跑
```

## 五、对明日日常产出的影响评估

### 5.1 不受影响（不依赖 baostock）

| 任务 | 时间 | 数据源 |
|------|------|--------|
| up.py 早盘 | cron 7:50 | akshare 涨停池 |
| slow.py + stock.py | cron 8:50 | akshare |
| PushPlus 通知 | stock 9:05 | 本地 md |
| morning-sync 写 trades | 8:50 后 | 读 md/json |
| 15:05 收盘补全 | cron | 新浪分钟 + 腾讯日线 |

### 5.2 可能受影响（需确认）

| 项 | 风险 | 处理 |
|----|------|------|
| `stock_UI.py` 码表加载 | 若触 baostock login | 启动 UI 时 `DISABLE_BAOSTOCK=1` |
| 手动点「强制重拉」大批量 | 接口限流 | 仅补空值；单次 ≤20 笔 |
| akshare/东财自身限流 | 网络抖动 | 已有 retry；勿 force 连续点 |

### 5.3 明日检查清单

```bash
# 1. 确认无回填进程
pgrep -fl backfill || echo OK

# 2. 确认暂停文件在
cat 每日交易记录/data/BACKFILL_PAUSED

# 3. 看昨日 cron 日志
tail -50 /tmp/daily_close_job_logs/cron.log
tail -50 /tmp/morning_all_models_logs/cron.log

# 4. 收盘后看补全是否成功
grep -E '完成|失败|exit=' /tmp/daily_close_job_logs/cron.log | tail -5
```

## 六、事故复盘（2026-08-20）

**原因**：`backfill_stock_year.py --source baostock --workers 6` 类任务，多线程并发 + 每线程/每失败重试 login，触发 baostock 反爬永久封禁。

**处置**：

1. 立即停止所有回填进程  
2. 启用 `BACKFILL_PAUSED`  
3. daily cron 增加 `DISABLE_BAOSTOCK=1`  
4. 2025 历史数据改日慢慢补，优先 `--source tx` / 同花顺  

**教训**：免费行情接口不是数据库，**login 是稀缺资源**，只能单进程低频使用。
