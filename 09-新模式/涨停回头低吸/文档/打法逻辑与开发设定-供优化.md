# 涨停回头低吸 — 打法逻辑与开发设定（供优化）

> 日期：2026-10-29  
> 读者：自己（白话综合版）  
> 依据：现行代码（`rules.py` / `services/*` / `jobs/*`）+ 已确认规格；**以代码为准**，规格冲突处单独标出。

## 白话摘要

这套打法是：**主板首板涨停 → 等 3～5 天回调到 10～20 日线之间低吸 → 半仓建仓、可补半仓 → 最多同时拿 2 只 → 破 30 日线或亏 6% 止损，涨停次日溢价必卖，最多拿 7 个交易日**。

工程上拆成三层池子、三条定时线；规则常量集中在 `rules.py`，改阈值先改这里。下文按「策略链 → 数字设定 → 工程设定 → 规格漂移 → 可优化清单」写，方便你对照改。

---

## 1. 策略一句话与三层池

**结论**：钱只在「持有池」里进出；涨停池是原料，观察池是待买名单。

| 层 | 作用 | 进出要点 |
|----|------|----------|
| **涨停池** | 近几日「首次一板」候选仓库 | 扫描写入；过观察窗未晋升则失效 |
| **观察池** | 已进入低吸窗口、可自动/手动买 | 调整第 3～5 天 + 价在 10～20 日线之间；超窗失效 |
| **持有池** | 真实仓位与卖出纪律 | 最多 2 只；先卖后买 |

状态流转（简化）：

```
涨停扫描命中 → 涨停池(in_pool)
        ↓ D3–D5 且落在低吸区间（适宜度排序，可多只）
观察池(watching)
        ↓ D3–D4 建仓 / D4–D5 阴线或十字星补仓
持有池(holding)
        ↓ 止损 / 涨停次日退出 / 第7日到期
已卖出 / 已止损；观察记录标 bought 或 expired
```

策略心得（文案口径，不要写成相反逻辑）：涨停确认趋势；调整是清洗浮筹的布局窗；主买 30 元以下、**低吸为主、跟随为辅**；纪律与耐心。

## 2. 入选与过滤（涨停池）

**结论**：入涨停池必须「主板首板 + 硬过滤」；软过滤（上市年限 / PE / 分红）可在补跑时跳过。

### 2.1 硬条件（扫描必过）

| 条件 | 现行设定 | 代码落点 |
|------|----------|----------|
| 主板 | 代码前缀 600/601/603/605/000/001/002/003 | `MAIN_BOARD_PREFIXES` |
| 非 ST | 名称含 ST 剔除 | `is_st_name` |
| 股价 | ≤ **30** 元 | `MAX_PRICE` |
| 只做首板 | 东财「连板数」必须 = **1** | `_reject_reason` |
| 近 10 日首次涨停 | 涨停日窗口内仅此一板（严格交叉校验） | `LOOKBACK_LIMIT_UP_DAYS=10` |
| 排除一字板 | 炸板次数=0 再查 OHLC；确认为一字则拒 | `is_yizi_limit_up` |

### 2.2 软条件（默认真扫要过；`--skip-soft` 可跳过）

| 条件 | 现行设定 |
|------|----------|
| 上市 | ≥ **5** 年 |
| 市盈率 | 0 \< PE-TTM \< **28** |
| 分红 | 连续两年分红率 ≥ **20%** |

### 2.3 扫描节奏

- 早盘流水线默认扫近 **8** 个交易日涨停（`MORNING_SCAN_DAYS`）；规则里另有「近 5 日」常量用于其它入口。
- 涨停池写入时**不要求**已在低吸区间（区间是进观察池才卡）。
- 均线系列可后补，避免扫池卡死。

## 3. 观察池：何时算「适合低吸」

**结论**：自动进观察 = 调整第 **3/4/5** 天，且现价满足 **20 日线 \< 价 \< 10 日线**，且 **10 日线 \> 20 日线**。

### 3.1 调整天数怎么算

- 涨停日 = T（第 0 天）
- **涨停后第 1 个交易日 = 调整第 1 天（D1）**
- 观察窗：`WATCH_ADJ_DAYS = (3, 4, 5)`
- 超窗（\>5）仍在涨停池 → 标失效；已在观察池 → 标超时失效

### 3.2 低吸区间

```
in_dip_zone ⇔ ma20 < 现价 < ma10  且  ma10 > ma20
```

### 3.3 适宜度排序（多选，不是一天一只）

排序键越小越优先：

1. **更早的调整日优先**：D3 \> D4 \> D5  
2. **同日内更深低吸优先**：价更靠近 20 日线（`dip_depth` 更大）

同时观察中上限默认 **30** 只（`WATCH_MAX_ACTIVE`）。手工加入观察可 `force` 跳过 D3–D5/区间校验。

## 4. 买入与补仓（观察 → 持有）

**结论**：只能从观察池买；同时最多 **2** 只；首次半仓，符合条件再补半仓。

| 动作 | 窗口 | 条件（现行代码） | 仓位 |
|------|------|------------------|------|
| **建仓** | 调整第 **3～4** 天 | 在低吸区间；有价；持仓未满 2 | **50%** |
| **补仓** | 调整第 **4～5** 天 | 已持有同标的且未满仓；K 线为**阴线或十字星**（持续阳线不加） | 再 **50%** |
| 超时未买 | 调整第 \>5 天 | 观察记录失效 `timeout_no_buy` | — |

其它约定：

- 参考跌幅阈值：当日涨跌幅 ≤ **-3%**（`BUY_DROP_PCT`）——见下文「规格漂移」：现网盘中任务里时间条件几乎恒真，实际更偏「在区间就买」。
- 建仓参考时点文案对齐 **14:30**；监控档位有 morning / midday / tail。
- 买入价默认可被人工改；锁定后自动任务不覆盖。

---

## 5. 卖出纪律（持有 → 结束）

**结论**：优先级大致是 **止损 / 涨停次日退出 \> 第 7 日到期**；涨停收盘当天不卖。

| 优先级 | 规则 | 状态/原因 |
|--------|------|-----------|
| 高 | 现价 **\< 30 日线**，或浮亏 **≤ -6%**，或触及展示止损价 | `stopped` / `stop_loss` |
| 高 | 前一日涨停收盘挂了「次日退出」：次日**有溢价高开也卖、无溢价也卖**（优先用开盘价） | `sold` / `limit_up_next_gap` 或 `limit_up_next_flat` |
| 中 | 持有满 **7** 个交易日（买入日=第 1 日） | `sold` / `day7_close` |

说明：

- 展示止损价 = 买入价 × 0.94；MA25 仅展示对照，触发主看 MA30 与 -6%。
- 涨停收盘：盘后或尾盘确认封板后设 `await_limit_up_exit`，**当日不卖**。
- 规格写「第 7 日约 14:00」；代码按持有天数 ≥7 在各监控档触发（未死卡 14:00 时钟）。

| `IRON_RULES.md` / `README.md` | 铁律与速查 |

### 6.3 交易日流水线（顺序不可乱）

| 时刻 | 阶段 | 动作 |
|------|------|------|
| **09:24–09:29** | 竞价写库 | 只落库，本项目不发 PushPlus |
| **09:40** | ①涨停池 → ②观察池 → ③持有 | 持有：**先卖后买**；现价 |
| **11:25** | 持有监控 | 止损 / 强势涨停挂次日 / 补仓节奏 |
| **14:30** | 持有监控（尾盘） | 对齐建仓参考时点 |

铁律：

1. 腾讯实时行情 **每次 1 只**，间隔约 0.45s，禁止批量拼接。  
2. **本项目不发 PushPlus**（早盘通知归首板 `stock_updata`）。  
3. crontab **禁止**外层 `>> /tmp/...` 重定向（见项目铁律说明）。

### 6.4 UI 与人工干预

- 三层筛选、行内编辑；自动价可改，锁定字段防覆盖。  
- 人工可绕过部分扫描直接加观察 / 买入，但仍受「最多 2 只持仓」约束。  
- 启动：`python zt_pullback_UI.py`（默认本机约 5055 端口）。

## 7. 规格 vs 现行代码（优化前必看的漂移）

**结论**：旧 V1 / 部分 V2 段落与现网不一致；改规则前以本节 + `rules.py` 为准。

| 点 | 旧文/口头 | 现行代码 |
|----|-----------|----------|
| 同时持仓 | V1 写「一轮一只」 | **最多 2 只** |
| 首仓比例 | V2 某段写过全仓 | **半仓 50% + 可补 50%** |
| 进观察是否要在区间 | V2 Q3：入观察可不在区间 | **自动晋升必须已在低吸区间**（涨停池仍可不在区间） |
| 买入触发 | 14:30 **或** 跌 ≤-3% | 盘中 `time_ok` 几乎恒为真 → **区间内易直接建仓**，跌幅条件弱化 |
| 第 7 日卖点 | 约 14:00 | 持有天数 ≥7 即在监控档卖，**未死卡 14:00** |
| 池结构 | 早期「观察+持有」双 Tab | 已落地 **涨停 / 观察 / 持有** 三层 |

优化时建议：先定「要以哪一版业务为准」，再改常量或收紧 `check_buy_signals` 条件，避免文档与自动单打架。

## 8. 可优化清单（供你圈选）

下面只列杠杆，不替你拍板。

### 8.1 选股过滤

- 股价 30 / PE 28 / 分红 20% / 上市 5 年：哪些改软、哪些保留硬？  
- 「仅首板」是否过严（是否允许弱转强二板）？  
- 一字板判定在炸板缺失时是否过松/过严？

### 8.2 观察与适宜度

- 观察窗是否仍锁死 D3–D5？要不要 D2 预告、D6 例外？  
- `dip_depth` 权重 vs 调整日权重，要不要加量能、板块强度？  
- `WATCH_MAX_ACTIVE=30` 是否过大导致名单噪音？

### 8.3 买卖触发

- 建仓是否强制「14:30 或 跌幅≤-3%」二选一真正生效（收紧现网恒真的时间条件）？  
- 补仓是否仍禁止阳线；十字星阈值 25% 实体是否要调？  
- 同时 2 只 vs 1 只；半仓 vs 其他比例。

### 8.4 风控与退出

- -6% 与破 MA30 是否改为「且」；是否回到破 25 日线？  
- 涨停次日「无溢价也卖」是否过狠；要不要给弱溢价留半仓？  
- 第 7 日是否改为「仅尾盘 / 仅 14:00」以免早盘误卖。

### 8.5 工程与数据

- 竞价写库与 9:40 流水线的依赖、失败重试。  
- 软过滤数据源稳定性（PE/分红缺失时 skip-soft 比例）。  
- 回测口径：用收盘价复盘 vs 用当时现价档位，避免未来函数。
