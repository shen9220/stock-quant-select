## 1. 总体目标与约束

### 1.1 目标

构建本地可运行的「涨停回头低吸」交易辅助系统：

1. **每日扫描**符合基础条件的股票 → 写入 **涨停观察池**。  
2. 观察池跟踪均线 / 调整进度；满足买入规则后生成买入参考价 → **买入持有池**。  
3. **同一时刻最多 2 只「持仓中」**（半仓×2）；满仓时不得新开；卖出后才能再买。  
4. 卖出后生成完整交易记录（盈亏可复盘）。  
5. 前端双 Tab（观察池 / 持有池）：筛选、编辑、删除（二次确认）、新增（少量字段，其余自动补全）。  
6. 定时任务每日拉取行情并回填均线、买入/卖出参考价。

### 1.2 硬约束（实现时必须校验）

| # | 约束 |
|---|------|
| C1 | 同时最多 **2** 条 `status=holding`；已满时自动买入 **跳过并写日志**；卖出腾出名额后方可再买 |
| C2 | 自动买入只针对观察池中「可买入」标的；人工「新增买入」可绕过扫描，但仍受 C1 约束 |
| C3 | 所有「自动价」仅为参考价，**允许人工编辑覆盖**；覆盖后设 `buy_price_locked` / `sell_price_locked`，后续自动任务不得覆盖锁定字段 |
| C4 | 利润率、是否盈利由买卖价自动计算；人工改价后立即重算 |
| C5 | 交易日日历必须用真实 A 股交易日（复用现有 `price_service` / baostock 交易日能力优先） |

### 1.3 业务闭环（状态机）

```
[扫描命中] → OBSERVING（观察中）
                │
                ├─ 调整期满未触发 / 均线破坏 / 人工失效 → EXPIRED（已失效）
                ├─ 买入触发（自动或手动）且无持仓 → HOLDING（持仓中）  ※观察记录标记 bought
                │
HOLDING ────────┼─ 破 MA30 或 ≤-6% → STOPPED（已止损）
                ├─ 涨停收盘→次日溢价退出 → SOLD
                └─ 持有第 7 交易日 14:00 → SOLD（已卖出·到期）
```

## 3. 术语与可编码定义

| 术语 | 编码定义 |
|------|----------|
| 主板 | 代码匹配：`^(600\|601\|603\|605\|000\|001\|002\|003)\d{3}$`。排除创业板/科创板/北交所/B 股 |
| 非 ST | 名称不含 `ST`、`*ST`、`S*ST`（大小写不敏感） |
| 股价 ≤ 30 | 使用**最新收盘价** ≤ 30.00（扫描日） |
| 上市满 5 年 | `(scan_date - list_date).days >= 5*365`（可用 1825 天；闰年可忽略） |
| PE < 28 | `0 < pe_ttm < 28`；PE 缺失或 ≤0 → 不入选 |
| 连续 2 年分红且分红率 ≥20% | 最近两个完整会计年度，每年：`现金分红合计 / 归母净利润 >= 0.20`，且净利润 > 0；缺数据 → 不入选 |
| 最近 10 交易日首次涨停 | 令昨日为 `D-1`：`is_limit_up(D-1)=true`，且对 `D-2 … D-10` 均 `is_limit_up=false`（共回溯 10 个交易日窗口，含昨日） |
| 涨停判定（主板非 ST） | 收盘价相对前收涨幅四舍五入到 2 位 ≥ 9.9%（或等于官方涨停价）；**收盘必须封在涨停价** |
| 一字板 | 涨停日：开盘价 = 涨停价，且全日未打开（或最低价 = 涨停价）→ **扫描排除** |
| 涨停日 T | 满足「昨日首次涨停」时的昨日日期 |
| 涨停后一日开盘价 | `T+1` 开盘价，字段 `t1_open` |
| 调整第 N 天 | **默认**：`adj_day = trading_days_between(T, today)`，即 T+1→1，T+2→2… |
| MA(N) | 最近 N 个交易日收盘价简单均值（含当日已收盘价）；盘中任务可用「昨收序列 + 当日最新价」近似，盘后必须用正式收盘重算 |
| 低吸区间 `in_dip_zone` | `ma20 < last_price < ma10` **且** `ma10 > ma20` |
| 持仓第 K 天 | 买入日 = 第 1 个交易日；下一交易日 = 第 2… |

## 4. 每日扫描条件（入观察池）

**执行时机**：交易日 **09:40**（日更；涨停池写入 + 观察池晋升 + 持有买卖扫描）。盘后可用同一入口 `--force` 补跑。  
**逻辑**：以下条件 **全部 AND** 通过才入**涨停池**；观察池另见晋升条件（D3–D5 + 低吸区间）。

| 序号 | 条件（对齐用户口述） | 实现要点 |
|------|----------------------|----------|
| S1 | 股价不超过 30 元 | 最新收盘 ≤ 30 |
| S2 | 只选主板票 | 见主板正则 |
| S3 | （用户列表无第 3 条，保留编号空隙，勿自造条件） | — |
| S4 | 最近 10 天首次涨停 | 昨日涨停且此前 9 日内无涨停 |
| S5 | （买入阶段条件，不作为入池硬门槛） | 见 §5；入池后每日更新 `in_dip_zone` |
| S6 | （买入阶段：等待 3～5 天） | 见 §5 |
| S7 | （卖出阶段止损） | 见 §6 |
| S8 | 主板 + ≤30 + 非 ST + 上市满 5 年 + PE\<28 + 连续 2 年分红率≥20% + 最近 10 天且昨日首次涨停 | 本表核心扫描包 |
| S9 | 【默认补充】排除涨停日一字板 | Q9 |

**入池动作**：

1. 以 `(stock_code, limit_up_date)` 为业务唯一键；已存在则 **跳过**（可刷新名称/板块/均线）。  
2. 自动补全：代码、名称、行业、概念（占比最大一个）、`t1_open`（若 T+1 已收盘）、MA10/20/25/30、最新价、`adj_day`、`in_dip_zone`。  
3. `status = observing`，`entered_at = scan_date`。  
4. **不自动买入**；仅放入观察池供跟踪。

**明确不做（避免与口述冲突）**：

- 入池 **不要求** 已回调到 MA10～MA20 之间（【默认】Q3）。  
- 入池不要求量能阈值；量能仅作前端展示可选扩展字段 `volume_note`（V2.1）。

## 5. 买入原则（观察 → 持有）

### 5.1 人工原则（复盘文案 / 操作指引）

- 调整约 **3～5 天**；**最好第 3～4 天开始建仓**，第 **4～5 天若继续调整则补仓**。  
- 股价应处于 **20 日线与 10 日线之间**（`in_dip_zone=true`）更优；【默认】自动买入时 **要求** `in_dip_zone=true`，否则只提示不自动成交。  
- 每次最终只选一只，全仓持有。

### 5.2 自动买入价同步（可编码）

对每条 `status=observing` 且未被标记失效的记录，在交易日盘中执行：

**窗口**：调整第 `adj_day ∈ {3,4,5}`。

**建仓触发（写入买入参考价，首次）** — `adj_day ∈ {3,4}`，且当前无 `holding`，且 `in_dip_zone=true`：

| 触发器 | 条件 | 参考价 |
|--------|------|--------|
| 时间 | 当日本地时间 ≈ **14:30**（允许 ±5 分钟，任务每 1～5 分钟轮询即可） | 当时最新价 |
| 跌幅 | 当日涨跌幅（相对昨收）≤ **-3%** | 触发瞬间最新价 |

二者 **OR**；同一标的 **只建仓一次**。

**补仓触发（可选）** — 已建仓且同一标的仍持仓，`adj_day ∈ {4,5}`，且当日继续走弱（例如再触达 ≤-3% 或再次到 14:30 且价 < 成本）：

- 系统 **只弹提示 / 写 `add_suggest_price`**，不强制下单；用户确认后更新：

```
buy_price = (旧成本 * 旧仓位比例 + 新价 * 新仓位比例) / 总仓位比例
```

【默认仓位】首次 100%；若用户做补仓，前端让用户填本次仓位占比（默认建议 50/50），系统存加权成本。首次自动建仓按全仓记 `position_pct=100`。

**T+5 / adj_day>5 仍未建仓**：

- `status → expired`，`expire_reason = timeout_no_buy`。  
- 仍允许人工「新增买入」从历史观察记录拉数据。

### 5.3 买入后数据迁移

自动或确认买入后：

1. 持有池新建一条记录（可复制观察池快照字段）。  
2. 观察池该条 `status → bought`（保留在观察池列表，可用筛选隐藏）。  
3. 填入：`buy_date`、`buy_price`、`status=holding`。  
4. 若用户未确认实际成交：可先 `status=pending_confirm`；【默认】为减少卡住，自动写入 `holding`，UI toast「已写入参考买入价，请核对」。

### 5.4 前端「新增买入」

弹窗必填：

- 股票名称（或代码）  
- 买入日期  
- 买入价  

保存后后台：

1. 解析代码 / 官方名称。  
2. 推断最近一次符合「10 日首次涨停」的涨停日；找不到则要求用户补填涨停日期。  
3. 自动补全板块、开盘价、均线等。  
4. 受 C1 约束：若已有持仓 → 拒绝并提示。

## 6. 卖出原则（持有 → 结束）

优先级从高到低：

### 6.1 止损（原则 1）

止损放宽为两条件**任一**即卖：

1. 最新价 **跌破 30 日线**：`last_price < ma30`  
2. 浮动盈亏 ≤ **-6%**：`last_price <= buy_price * 0.94`  

→ `sell_reason=stop_loss`，`status=stopped`。  
展示止损价 = `buy * 0.94`；另展示 25/30 日线对应止损收益% 供对照。  
买入仍在 10–20 日线低吸区间；止损不再用「破 25 且 -3%」窄口径。

### 6.2 止盈 / 涨停处理（原则 3）

**涨停收盘当日不卖**（拿到涨停收盘继续持有），写入 `await_limit_up_exit=true`。

**次日开盘看溢价**（两情况都卖）：

- 高开有溢价 → 按开盘价（或早盘价）卖出，`sell_reason=limit_up_next_gap`  
- 平开/低开无溢价 → 同样卖出，`sell_reason=limit_up_next_flat`  

不再使用「盘中触及涨停 / 冲高 7%」当日强卖（避免如新中港涨停日被误卖）。

### 6.3 到期卖出（原则 2 + 自动卖出价）

- 持有 **不超过 7 个交易日**；**最迟第 7 个交易日 14:00** 卖出全部，不看利润。  
- 自动任务：`hold_day == 7` 且时间 ≈ **14:00**（±5 分钟）→ 参考价 = 当时最新价，`sell_reason=day7_close`，`status=sold`。

### 6.4 计算字段

```
profit_rate = (sell_price - buy_price) / buy_price * 100   # 保留 2 位小数，单位 %
is_profit = profit_rate > 0                               # 展示「是/否」
hold_days = 交易日计数（买入日=1 … 卖出日）
```

未卖出时：`profit_rate` / `is_profit` 按最新价显示浮动盈亏，持有池列名 **收益率%**；卖出后用卖出价锁定。

### 8.3 观察池操作

| 操作 | 行为 |
|------|------|
| 新增 | 必填：股票名称、涨停日期 → POST 后自动补全其余字段 |
| 编辑 | 弹窗，几乎全字段可改；保存 PUT |
| 删除 | `confirm('确认删除观察记录 #id？')` → DELETE |
| 行内快捷 | 可选「标记失效」 |

### 8.4 持有池操作

| 操作 | 行为 |
|------|------|
| 新增买入 | 必填：股票名称、买入日期、买入价 → 自动补全；校验无第二持仓 |
| 编辑 | 全字段可改；改买卖价重算利润 |
| 删除 | 二次确认 |
| 手动卖出 | 可在编辑里填卖出价/日期，或单独「卖出」按钮 |

## 9. 定时任务与数据同步

| 任务 |  cron 建议 | 行为 |
|------|------------|------|
| daily_scan | 交易日 15:30 | §4 扫描入观察池 |
| update_ma | 交易日 16:00 | 更新两池所有未锁定均线 + last_price + in_dip_zone + adj_day |
| monitor_buy | 交易日 09:35–15:00 每 1～5 分钟 | §5.2 买入/补仓提示；重点在 14:25–14:35 |
| monitor_sell | 交易日 09:35–15:00 每 1～3 分钟 | §6.1 / §6.2 |
| day7_sell | 交易日 14:00 | §6.3 |
| heartbeat_log | 每次任务 | 写 `data/logs/YYYYMMDD.log` |

**均线每日同步**：即使用户未打开页面，盘后任务也必须跑完；UI 打开时提供手动「刷新均线」。

**买入价自动同步**：满足 §5.2 即写入；支持编辑。  
**卖出价自动同步**：默认第 7 日 14:00；若已因止损/强势卖出则 **不再** 被 day7 覆盖（除非未 lock 且 sell_reason 为空的异常修复场景）。

## 12. V1 文档问题修正清单（相对旧版 md）

1. 扫描条件与「MA 区间」解耦：MA 区间属买入过滤，非入池硬条件（除非用户改 Q3）。  
2. 「开票」统一为「开盘」。  
3. 卖出价「固定第 7 日 14:00」与止损/强势卖出并存时明确优先级。  
4. 「同时一只全仓」写成 API 硬约束。  
5. 补仓与全仓关系默认「首次全仓参考价 + 可选补仓加权」。  
6. UI 明确对齐 Flask 单页，而非空泛 React/Vue（可替换但默认 Flask）。  
7. 增加 lock 字段，避免自动任务覆盖人工改价。  
8. 增加状态机与唯一键，避免重复入池。  
9. 观察池保留 `bought/expired`，持有池保留历史 `sold`，便于复盘。  
10. 待确认表 Q1～Q10，防止 AI 臆造。
