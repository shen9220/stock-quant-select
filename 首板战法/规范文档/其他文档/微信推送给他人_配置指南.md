## 一、PushPlus 的三种推送方式

官方定义了三种，**`to` 和 `topic` 不能同时出现**：

| 模式 | 参数 | 发给谁 | 值的格式 |
|---|---|---|---|
| 一对一 | 不填 | 只发给你自己 | — |
| **好友消息** | `to` | 指定的一个/多个好友 | 32 位 hex **好友令牌** |
| 一对多 | `topic` | 群组里所有订阅者 | 自己定义的**群组编码**（短字符串） |

> 官方原文：「好友消息和群组消息不能同时使用，**请勿同时填写 to 和 topic**」。

**你目前走的是「好友消息」模式** —— 你在官网加了好友，好友令牌是 `87a31c4a…`，
这是 32 位 hex（群组编码不会长这样）。

## 三、怎么加更多人

### 方式 A：加为好友（当前用法，推荐）
1. 打开 <https://www.pushplus.plus/> → 公众号菜单「**好友**」→ 添加好友
2. 对方扫码确认成为你的好友
3. 复制该好友的**好友令牌**
4. 追加到配置文件（多人用逗号分隔）：

```
TO=87a31c4aebac40f1988ffc73624d9426,第二个好友令牌
```

- 官方限制：实名用户最多 10 人，会员 100 人。
- 优点：**不用建群、不用发二维码**，加谁就推给谁，可以精确控制。

### 方式 B：建群组（一对多）
1. 官网 →「发送消息」→「一对多消息」→ 新建群组
2. 群组类型选**公开群组**（订阅者无需登录即可扫码加入）
3. **群组编码**自己定，如 `quant-team`
4. 「查看二维码」发给对方，对方微信扫码订阅
5. 配置改成：

```
TOPIC=quant-team
```

- 优点：一次加多人，对方自助扫码进出，你能在后台管理订阅人。
- 缺点：多一步建群 + 发二维码。

### 怎么切换
直接改配置文件那一行的前缀：`TO=` 走好友，`TOPIC=` 走群组。
**两者不能同时出现在 payload 里**，代码里已强制互斥。

## 四、哪些通知会推给好友

用户明确：**你（本人）收全部通知；好友只收白名单类别，其余只发本人**。
> 注意：旧版曾把白名单类别「只发好友、漏掉本人」，已于 2026-10-27 修复为「本人+好友」双发。

| 通知 | 触发时间 | 脚本 | 好友可见 |
|---|---|---|---|
| **stock 模型通知** | 每交易日 **09:05** | `stock/stock.py` | ✅ |
| **STOCK 水下集合竞价** | 每交易日 **09:25** | `stock/stock_updata.py` | ✅ |
| **Stock V2 双路径** | **09:27–09:29 单次** | `最新一进二/stock_v2.py` | ✅ `stock_v2_notify` |
| **stock 周结果** | 当周最后交易日 **15:00** | `每日交易记录/push_weekly_result.py` | ✅ |
| stock Top2 买入涨跌幅 | 收盘后 15:00 | `每日交易记录/push_top2_result.py` | ❌ 只发你 |
| slow / up 选股通知 | 早盘 | `每日交易记录/send_push_notify.py` | ❌ 只发你 |

### 怎么实现的（通知类别 + 白名单闸门）

每条通知带一个 `kind` 标签，`send_pushplus()` 内部按白名单决定去向：

```
本人【永远】收件 → 默认 self 投递一定发生
kind ∈ FRIEND_KIND_WHITELIST  → 本人 + 好友 双发（两条独立请求）
kind ∉ 白名单（含没标 kind）  → 只发本人（不转发对外通道，fail-safe）
```

**白名单唯一事实来源**：`pushplus_notify.FRIEND_KIND_WHITELIST`
```python
FRIEND_KIND_WHITELIST = {KIND_STOCK_NOTIFY, KIND_STOCK_UPDATA, KIND_STOCK_WEEKLY, KIND_STOCK_V2}
```

要调整对外推送范围，**只改这一处**，其它脚本都引用 `pushplus_notify.KIND_*` 常量。

> 手动补发时显式传 `--to` 也遵循同一条规则：本人照收，白名单类别额外转发好友。

## 六、怎么判断值是好友令牌还是群组编码

PushPlus 对两者都会**同步校验**，无效时返回 `code=999`：

| 情况 | 返回 |
|---|---|
| 无效 `to` | `data=接收用户未关联到公众号` |
| 无效 `topic` | `data=群组信息不存在` |
| **有效值** | `code=200 执行成功` |

所以直接发一次看返回码就能判定 —— 本项目已用这个方法确认过当前值是**有效的好友令牌**。

## 八、注意事项

- **异步投递**：同步返回 200 只代表「服务端收到请求」，不代表好友已收到。
  要查真实投递状态需要 access-key（个人中心 → 接口设置）：
  ```python
  from pushplus_notify import query_send_result
  query_send_result("b7d7770d1a9443a5915ef241d9fbc4f4", access_key="你的key")
  # → {"status": 2, "errorMessage": "", ...}   status: 0未投递/1发送中/2已发送/3失败
  ```
- **好友令牌是敏感信息**，别发到公开渠道、别贴进 GitHub。
- 对方可以随时解除好友关系。
- 想临时关掉对外推送：把配置那行前面加 `#`，或删掉 `topic.md` —— 立刻退回只推自己。
- PushPlus 有发送频率限制，注意别开太高频。
