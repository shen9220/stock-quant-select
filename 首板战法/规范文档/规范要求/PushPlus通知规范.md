> 代码闸门：`公共/pushplus_notify.py` 的 `FRIEND_KIND_WHITELIST` / `KIND_*` / `test` / **单次串行回执** 必须与本表一致。

## 0. 总原则

| 规则 | 说明 |
|------|------|
| 本人 | 下表「本人」列为 ✅ 的全部接收 |
| 好友 | **仅**「好友」列为 ✅ 的接收；未列或 ❌ 的绝不转发 |
| 暂停 | 「暂停」节内不发 PushPlus（可照常跑选股落盘） |
| **测试** | **非规定时刻、手动触发的一律只发本人，不转好友**（见 §测试通知） |
| 改动 | 用户明确指示 → 改本文件 → 再改代码 |

机制：`send_pushplus(..., kind=...)` — kind ∈ 好友白名单 → 本人成功后再发好友；否则只发本人。  
测试：`test=True` / `--test` / `kind=test_notify` / `PUSHPLUS_TEST=1` → **强制只发本人**。

## ⛔ 第三方接口铁律（禁止性 · 最高优先级）

> **历史教训**：baostock 曾因批量并发调用被封禁；PushPlus 也曾因一轮连发多条触发 `code=999`。

| 编号 | 铁律 | 说明 |
|------|------|------|
| P0 | **禁止批量** | 禁止 for 循环 / 线程池 / 并行 /「一口气」对第三方接口连发多条请求 |
| P1 | **单次处理** | 任何第三方接口（PushPlus / baostock / 腾讯 / 通达信 / 东财等）**一次只处理一条请求** |
| P2 | **先回执再下一条** | 必须等上一条请求的**成功回执**（HTTP/业务成功，如 PushPlus `code=200`）返回后，才允许发下一条 |
| P3 | **失败即停或单条重试** | 失败可对**同一条**有限次重试；禁止失败后立刻改发下一批 unrelated 请求刷接口 |
| P4 | **Agent/脚本同罪** | 人工补发、收盘挂钩、早盘多通道：一律遵守；不得以「补发」「赶点」为由批量 |

PushPlus 特例：

- 一条业务通知若需「本人 + 好友」：先发本人 → 等回执成功 → 再发好友（仍算同一业务通知的两段串行，不是批量业务通知）。
- 收盘若有多条业务通知（V1 原日 / 创业板日 / 周结果）：**严格一条接一条**，上一条整段成功后再发下一条。

代码闸门：`公共/pushplus_notify.py` 进程内互斥锁 + `send_pushplus` 内本人→好友串行；收盘编排禁止并发 `_push_once`。

## 1. 早盘通知（本人 + 好友）

仅以下 **3** 条。好友可收。

| 代号 | 名称 | kind | 时刻 | 脚本 | 本人 | 好友 |
|------|------|------|------|------|------|------|
| a | stock-V1（早盘选股） | `stock_notify` | **09:05** | `stock-V1/stock-V1（默认原）/stock.py` | ✅ | ✅ |
| b | stock-V1 水下 | `stock_updata` | **09:25** | `Stock-V1（水下）/stock_updata.py` | ✅ | ✅ |
| c | stock-V2（早盘竞价） | `stock_v2_notify` | **~09:27** | `stock-V2/Stock-V2（一进二）/stock_v2.py` | ✅ | ✅ |

好友白名单（代码必须等于此集合；测试 kind **不得**加入）：

```text
stock_notify, stock_updata, stock_v2_notify
```

**09:05 必达（仅 A 股交易日）**：`morning_all`（08:50 进场 `--notify-at 09:05`）+ `morning_notify_watchdog`（缺则 `--notify-only` 补发）+ UI `_morning_scheduler_loop` 兜底。  
**非交易日（周末/法定休市）一律不推**：crontab 闸门、`_ensure_stock_notify`、`stock.py` 通知入口三层都必须拦；不得因 UI 兜底漏闸门在休市日重跑/重发（2026-10-31/11-01 实锤）。交易日不得因闸门误判 / 旧路径导致漏发。

## 2. 尾盘通知（仅本人 · ≥15:00）

未到 **15:00** 禁止发送（盘中 `--force` 补价不得触发）。好友 **全部不收**。

| 代号 | 名称 | kind | 触发 | 脚本 | 本人 | 好友 |
|------|------|------|------|------|------|------|
| e1 | V1 原当日买入涨跌幅 | `stock_top2` | 交易日 ≥15:00 收盘补全后 | `交易记录UI/jobs/push_top2_result.py`（program=stock） | ✅ | ❌ |
| e2 | V1 创业板当日买入涨跌幅 | `stock_chinext_top2` | 同上 | 同上（board=创业板） | ✅ | ❌ |
| g | V1 原周结果 | `stock_weekly` | 当周最后交易日 ≥15:00 | `交易记录UI/jobs/push_weekly_result.py`（program=stock） | ✅ | ❌ |

### 2.1 V1 原周结果内容口径

- **一条** PushPlus（禁止把周结果拆成多条连发）。
- 正文：排名 1 一节、排名 2 一节，**然后汇总**（沿用现有字段：当天收盘利润 / 早盘全卖 / 午盘全卖 + 本周总结项）。
- **只含全局 rank=1/2**；禁止把主板/创业板 `board_rank` 记成「排名 0」塞进本条。

### 2.2 尾盘发送顺序（单次串行）

```text
① V1 原当日买入涨跌幅  → 等回执成功
② V1 创业板当日买入涨跌幅 → 等回执成功
③（若本周最后交易日）V1 原周结果 → 等回执成功
```
