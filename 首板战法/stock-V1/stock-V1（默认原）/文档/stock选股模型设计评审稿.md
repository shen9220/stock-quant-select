## 0. 请评审方重点回答的问题

1. 候选池定义（「真首板」）是否过松 / 过严？漏掉或误杀哪类票？
2. 五因子综合得分的结构是否合理？量纲是否失控（尤其成交额、换手）？
3. 「全市场混排 Top2」是否优于「分板块再合成」？与主板/创业板独立 Top2 如何分工？
4. 哪些因子应加入 / 删除 / 改成相对排名（rank）而不是绝对分？
5. 基因、趋势的定义是否太粗糙？有没有可验证的替代指标？
6. 交易假设（D1 开盘买、D2 9:35/13:15 卖）与选股因子是否匹配？

请直接给：**保留 / 改公式 / 改池子 / 改产出数量**，并说明猜错后果。

## 1. 一句话目标

在 **A 股首板（连续涨停仅 1 天）** 池子里，用多因子综合得分挑出 **全市场强度最高的 2 只**，于 **下一交易日（D1）开盘买入**，再下一交易日按约定时刻卖出；结果写入交易 UI 的 **Stock** Tab，并可选 PushPlus 通知。

---

## 2. 交易与日期约定

| 符号 | 含义 |
|------|------|
| D0 | 涨停日 = 运行日的**前一交易日**（看盘日） |
| D1 | 买入日 = D0 的下一交易日 |
| D2 | 计划卖出日 = D1 的下一交易日；卖出价取 **09:35 / 13:15**（由收盘补全链路写价，不进本模型打分） |

- 买入价铁律：D1 **开盘价**（UI / 收盘任务负责，本模型只写 code/name/rank）。
- 本模型**不**在选股时判断「能否买进 / 一字板」；开盘涨停买不进由后续补价逻辑留档。

---

## 3. 端到端流程

```
运行日早盘（约 08:50）
    ↓
取 D0 东财涨停池
    ↓
去掉「D0 前一交易日已在涨停池」的票 → 只要首板
    ↓
排除 科创688 / 北交92 / ST
    ↓
逐只补：30日涨停基因、MA5>MA10 趋势、市盈率（展示用）
    ↓
综合得分排序 → 取 Top2
    ↓
写 results/{D0}_recommendations.md
同步 trades → 每日交易记录 UI（program=stock, rank=1/2）
可选：PushPlus 通知
```

数据源主路径：`akshare` 东财涨停池 `stock_zt_pool_em`；日线用于趋势；涨停池缓存避免「N 票 × 30 天」打爆接口。

---

## 4. 候选池规则（进池门槛）

| 步骤 | 规则 | 目的 |
|------|------|------|
| 1 | D0 必须在东财涨停池 | 当日涨停 |
| 2 | D0 的前一交易日 **不在** 涨停池 | 「连续 1 天涨停」= 首板，排除连板 |
| 3 | 代码不以 `688`、`92` 开头 | 去掉科创、北交 |
| 4 | 名称不含 `ST` / `st` | 去掉风险警示 |

**刻意不做的事（现状）：**

- 不按行业、市值、流通盘硬过滤  
- 不区分「换手板 / 缩量板 / 一字板」再分层  
- 不要求封单金额、炸板次数阈值  
- 不做「竞价异动 / 高开幅度」预判（那是买入日行为，本模型在 D0 收盘后选）

若 D0 前一交易日涨停池为空：当前实现视为「全部 D0 涨停股都算首板候选」（偏宽松）。

---

## 5. 综合得分公式（核心）

设计意图（注释口径）：涨幅 40%、成交额 20%、换手 20%、基因 10%、趋势 10%。  
**代码落地**如下（评审请以落地公式为准）：

\[
\begin{aligned}
\text{涨幅分} &= \min\!\left(\frac{\text{涨跌幅}}{\text{板块涨停上限}},\,1\right) \times 4 \\
\text{成交额分} &= \frac{\text{成交额}}{10^8} \times 0.2 \\
\text{换手分} &= \text{换手率} \times 0.2 \\
\text{基因分} &= \text{近30日涨停次数} \times 0.1 \\
\text{趋势分} &= \mathbf{1}[\text{MA5}>\text{MA10}] \times 0.1 \\
\text{综合得分} &= \text{涨幅分}+\text{成交额分}+\text{换手分}+\text{基因分}+\text{趋势分}
\end{aligned}
\]

### 5.1 板块涨停上限（只用于涨幅归一）

| 代码前缀 | 上限 |
|----------|------|
| 300 / 301 / 688 | 20% |
| 600 / 601 / 603 / 605 / 000 / 001 / 002 / 003 | 10% |
| 8* / 4*（北交等） | 30% |
| 其他 | 默认 10% |

**为何归一：** 旧版直接 `涨跌幅 × 0.4` 时，创业板涨停约 20% → 8 分，主板涨停 10% → 4 分，创业板结构性多 4 分。归一后两者涨停时涨幅项都约 **4 分**，榜首由成交额 / 换手 / 基因 / 趋势拉开。

### 5.2 附加指标定义

| 指标 | 定义 | 是否进得分 |
|------|------|------------|
| 历史涨停基因 | 以「今天」为终点，往回扫约 30 个**自然日**，统计有多少天该代码出现在当日涨停池 | 是 |
| 趋势指标 | 近约 30 日日线，收盘 MA5 > MA10 则为 1，否则 0 | 是 |
| 市盈率 | 基本面接口；失败则为 0 | **否**（仅报告展示） |

报告文案里还有「连板潜力 / 首板胜率」等话术（基因>5、趋势+基因>3 等），**不参与排序**。

### 5.3 产出规则

- 按综合得分 **降序**，取 **前 2 只** → Stock Tab `rank=1/2`
- 其余候选只写入报告「未入选原因：得分低于前二」
- **不做**板块配额；可能两只都是主板，或一主一创

### 5.4 数值量纲示意（帮助评审）

假设一只主板真涨停（涨幅分≈4）：

| 场景 | 成交额 | 换手 | 基因 | 趋势 | 粗算总分量级 |
|------|--------|------|------|------|----------------|
| 天量高换手 | 20 亿 → +4.0 | 30% → +6.0 | 7 → +0.7 | 0 | ≈ 4+4+6+0.7 ≈ **14.7** |
| 中等 | 7 亿 → +1.4 | 24% → +4.8 | 1 → +0.1 | 0 | ≈ **10.3** |

可见：**换手 ×0.2** 与 **成交额（亿）×0.2** 在高换手票上很容易压过「基因/趋势」；涨停后涨幅项近似常数，实际排序高度依赖 **额+换手**。

## 6. 与同目录其他模型的边界

| 模型 / Tab | 池子与目标 | 与 Stock 关系 |
|------------|------------|----------------|
| Stock（本文） | 全市场首板 → 综合分 Top2 | 主强度榜 |
| 主板 / 创业板 Tab | 同一首板逻辑思路，但 **按板块各自 Top2**（`board_rank`） | 展示分拆，不是 Stock 的子集拆分 |
| Slow | 另一套慢热 / 独立脚本 | 独立 program |
| Up | 强度涨停 up.py 权威 JSON | 独立 program |
| 水下 stock_updata | 绿开等水下口径 | 独立 program |

评审 Stock 时请 **不要** 默认「主板 Tab = Stock 里的主板票」；两者打分与写入字段不同。

## 7. 工程与运行约束（改模型时必须知道）

1. **取数限流**：涨停池按日缓存；禁止对历史日期批量并发狂刷。  
2. **早盘链路**：约 08:50 跑 `stock.py` 落盘+通知；09:30 UI 六 Tab 复检只保证记录写入，不重算因子。  
3. **Baostock**：生产侧可能长期不可用；Stock 主路径已偏东财/akshare。  
4. **幂等**：同一 D1 可重复 sync；以 code/rank 对齐 UI。  
5. **代码位置**：`01_量化模型/首板战法/stock/stock.py`；结果 `stock/results/`；成交 `stock/trades/`。

## 8. 已知弱点 / 自检清单（供评审开火）

以下是维护方已知或可疑的问题，欢迎证伪或提出替代方案：

1. **量纲未标准化**：换手 30 → +6 分，趋势满分仅 +0.1，趋势几乎摆设。  
2. **基因窗口按自然日扫涨停池**：含周末空窗、接口失败记 0；与「交易日 30 日」不一致；且以 `datetime.now()` 为终点，历史回放时可能偏「未来函数」风险（回测需单独冻结 as-of）。  
3. **趋势用「当前」日线窗口**，不是严格以 D0 为 as-of 的点-in-time。  
4. **市盈率算了但不进分**；报告里常为 0，噪音大。  
5. **Top2 固定**：没有「得分差过小则弃权 / 只推 1 只」的阈值。  
6. **一字板 / 高开买不进** 不在选股阶段处理，可能选出「看起来很强但 D1 买不进」的票。  
7. **行业扎堆**：不限制同行业两只。  
8. **注释权重 40/20/20/10/10 与代码不完全同构**（涨幅是 ×4 封顶，不是连续 40% 权重归一到 10 分制）。  
9. **与板块 Tab 双轨**：运维成本高，口径解释成本高。  
10. **样本与验证**：缺少本文档绑定的「样本外胜率 / 回撤 / 分年稳定性」表；改进应用回测说话。
