## 3. 库存与工期估算（核心）

**现状（2026-10-27 dry-run）**

- 窗口交易日：约 **195** 天（2026-01-05 ~ 10-27）  
- 已尝试 / 已有板块记录：约 **6** 天  
- **待补 ≈ 189 天**  
- 今年余下交易日（10-28 ~ 12-31）：约 **47** 天（补完 YTD 后，每日只需同步「今天」1 天）

**每晚吞吐设计（按你的 A 方案）**

- 找齐约 **8～10 条平台轨**  
- 每轨配额：**3 个交易日 / 晚**  
- 理论：`10 × 3 = 30 天/晚`  
- 现实折扣（某源空数据、重试、硬停提前收工）：按 **15～20 天/晚** 估

| 场景 | 每晚完成 | 189 天 catch-up | 说明 |
|------|----------|-----------------|------|
| 理想（10 轨全活） | ~30 天 | **约 7 个自然日** | 几乎每晚满额 |
| 基线（推荐对外承诺） | ~18 天 | **约 10～12 个自然日** | 允许 2～3 轨失败/空 |
| 保守（仅 5 轨稳定） | ~10 天 | **约 19～20 个自然日** | 东财/baostock 不稳时 |

**结论（给你拍板用）**

> 按「每天自动开跑 + 多源分轨」：  
> **今年 stock 主板/创业板 tab 倒序补完，大概率 1.5～2 周；理想约 1 周；最坏约 3 周。**  
> 补完后每晚只扫「当日 + 极少数失败重试」，分钟级结束，不再占满夜班。

单日成本（优化后，每轨）：

1. 涨停池 D0 + 前日：2 次（磁盘缓存命中则 0）  
2. **粗排**只用池内涨幅/成交额/换手 → 每板 Top8  
3. 仅对 ≤16 只做基因/趋势精算（禁止对整池 40+ 只打日线）  
4. `auto_enrich=False` 写 `board_rank`  
5. 请求间隔 ≥ 0.8～1.2s，失败指数退避，连续 3 次异常停该轨  

粗算每轨 3 天 ≈ 15～40 分钟；10 轨并行仍远小于 15:30→04:50 窗口。

## 4. 平台分轨（尽量凑满 ~10）

本机已装：`akshare`、`baostock`。未装：`efinance` / `mootdx` / `pytdx` / `tushare`（可选后装，不作为 P0 阻塞）。

### 4.1 角色拆分（避免「每轨都打同一类接口」）

| 角色 | 做什么 | 候选源（单线程） |
|------|--------|------------------|
| **Z 轨 · 涨停池** | 按日拉涨停池并落盘缓存 | ①东财 `stock_zt_pool_em` ②同花顺 THS ③东财备源/历史池封装 |
| **K 轨 · 日线/趋势** | 对粗排后的少数票取日线算趋势 | ④腾讯 `stock_zh_a_hist_tx` ⑤新浪日线 ⑥东财日线 ⑦baostock 日线（**单 login、极低速**） |
| **可选增强** | 装上再启用 | ⑧efinance ⑨mootdx/通达信 ⑩网易财经 |

### 4.2 每晚日期分配（互不重叠）

```
pending_dates = 倒序待补（已 attempted / 已齐 board_rank 的跳过）
lanes = [Z-em, Z-ths, K-tx, K-sina, K-em, K-bs, ...]   # 存活探测后动态裁剪
for i, lane in enumerate(lanes):
    lane.dates = pending_dates[i::len(lanes)][:3]   # 每轨最多 3 天
```

规则：

- **同一自然日只分配给一条轨**（汇总写盘无冲突）  
- 轨与轨可并行（不同进程），轨内严格串行  
- 某轨连续失败 → 当晚退出该轨，日期回池次日重派  
- 全局进程锁 + 每日期文件锁，禁止双写同一 `trades/YYYY-MM-DD.json`

### 4.3 数据汇总

每轨产出临时 JSON（`data/board_lane_out/{date}_{lane}.json`）→ orchestrator 校验后调用现有 `upsert` + 二次写 `board_rank` → 更新 `backfill_board_state.json` 的 `attempted`。
