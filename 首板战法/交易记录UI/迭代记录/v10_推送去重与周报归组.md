# v10 推送去重 + 周报归组修正

日期：2026-10-23
触发：用户反馈「当天收盘通知和周结果每个都通知了两遍；周结果缺少今日卖出的数据」

## 一、重复推送（两个问题叠加）

### 现象
同一天里 `stock Top2 买入结果` 与 `stock 周结果` 各收到两条一模一样的推送。

### 根因
1. **两套调度同时在跑收盘补全**
   - `stock_UI.py` 进程内的 `start_close_scheduler()` 线程：15:00 等待 45s 后跑全部程序（日志落到 `/tmp/stock_ui.log`）；
   - 15:05 的外部兜底 CLI：`daily_close_job.py --all-programs`（日志落到 `data/daily_close_logs/cron.log`）。
2. **去重不原子**
   原逻辑是「读 state → 判断是否推过 → 发送成功 → 再写 state」。
   两个进程在 15:00 附近并行时都可能读到「今日未推送」，于是各发一次；
   发送失败时也不会回滚，容易漏推或重复推。

### 修复
- 新增 `daily_close_job._push_once(state_key, value, sender, label)`：
  **抢文件锁 `data/push_once.lock`（fcntl.flock）→ 重新读 state → 占位落盘 → 释放锁 → 再发送**。
  占位先写盘，另一进程随后进来必然看到已占位而跳过；发送失败回滚占位，下一轮可重试，不漏发。
- 新增 `daily_close_job._skip_if_done(program, day, force)`：
  15:05 的兜底 CLI 若发现 `last_close_run_date_{program} == today` 且买入同步无未完成项，直接跳过，
  不再白跑一遍补全（`--force` 可强制重跑）。
- 自测：两个进程并发调用 `_push_once`，只有 1 次真正发送；失败路径回滚后可重试成功。

## 二、周结果缺「今日卖出」

### 现象
10-19~10-23 周报只有 4 只票，缺 10-22 买入、10-23 卖出的 `300006 莱美药业`、`603629 利通电子`。

### 根因（两层）
1. **缺价被当作「卖不出」而滚动卖出日**
   `price_service.resolve_sell_day_prices()` 里，`分钟价缺失` 与 `涨停卖不出` 走同一条顺延分支，
   10-23 的 5 分钟柱未落库 → `sell_date` 被滚到 10-26，卖出价留空。
2. **周报按 `sell_date` 严格归组**
   `push_weekly_result._collect_week()` 只收 `monday <= sell_date <= friday`，
   `sell_date` 一旦漂到下周，这一票就整条丢出本周。

### 修复
- `price_service`：`分钟价缺失` / `尚未开盘` 不再顺延卖出日，原地记 `pending_935 / pending_1315`，
  等数据落库后同一天补齐（禁止用错日期取错价）。涨停/跌停仍按原规则顺延。
- `push_weekly_result._collect_week()` 归组改为：
  1. `sell_date` 落在本周 → 用 `sell_date`；
  2. `sell_date` 缺失或被滚出本周 → 回落到**计划卖出日**（买入日的下一交易日）；
     只要计划卖出日在本周就计入本周。一票只归一周，不跨周重复。
- 周报增加脚注：`N 条 09:35/13:15 分钟价未落库，早/午盘利润显示 --`。
- 修复存量脏数据：`stock/trades/2026-10-22.json` 两只票 `sell_date` 由 2026-10-26 改回 2026-10-23
  （价格仍空，等 baostock 10-23 分钟柱落库后由下一轮收盘补全自动填）。
- 已按修正后的口径重发 `stock 周结果 2026-10-19~2026-10-23`。

## 五、为什么 15:00 老是补不到 D2 卖价（根因 + 修复，16:20）

用户口径：「正常只有当天买入的拿不到卖出价，其他都该拿到」。

实测（2026-10-23）：
- 15:00 / 16:00 查 baostock `query_history_k_data_plus(frequency="5")`，10-23 返回
  `error_code=0` 但 **0 行**；连 `frequency="d"` 的当日日线也是 0 行。
- 说明 baostock 的当日 EOD（含 5 分钟柱）**收盘后要过一段时间才发布**，
  15:00 的收盘补全时点根本取不到 —— 这不是代码算错，是数据还没生成。
- 2026-10-16 加的「baostock 可达但缺数据时禁止降级新浪」把这种情况判成了「口径异常」，
  直接返回 None → 10-19 起 D2 卖价连续为空，`sell_date` 还被滚到下一交易日，
  周报整条丢票。

修复：
1. `_fetch_minute_baostock` 对「0 行」返回**空 DataFrame**（不再返回 None），
   上层可区分「该日未发布」与「接口失败」。
2. 新增 `get_minute_price_ex()`：baostock 有值 → `baostock_5m`；
   baostock 该日 0 行 → 用新浪 1 分钟兜底 → `sina_1m`，并打印明示日志。
   `get_minute_price()` 保持原签名（返回价格），老调用点不受影响。
3. 来源写入交易记录：`sell_price_source / _935 / _1315`（`sina_1m` 与 `baostock_5m` 可区分）。
4. **新浪直连兜底**：新增 `_fetch_minute_sina_http()`，直接打
   `quotes.sina.cn/.../getKLineData`。原因：15:05 的外部兜底 CLI 用 `/usr/bin/python3`
   （没装 akshare），旧的新浪兜底实际是死代码（`ak is None`）。直连后任何解释器都能兜底。
5. **补价重试窗口**：`daily_close_job` 调度器在 15:30~20:30 每 30 分钟检查一次
   「应卖出日已到但 09:35/13:15 仍空」的记录，有缺口就重跑补价（每天最多 8 次）；
   涨停/跌停顺延到未来日的不催。
6. 顺带补齐历史缺口：slow/up/stock_updata 10-21、10-22 共 9 条被滚坏卖价，
   已重新解析并回填（10-22 及更早走 baostock_5m，10-23 走 sina_1m）。
   601999 出版传媒 10-23 13:15 = 7.72 正好跌停（前收 8.58，跌停价 7.72），
   属「卖不出」，按规则顺延，保持空值等 10-26。

- 同日 baostock 未发布 → 新浪兜底成功；10-22（已发布）→ `(8.54, 'baostock_5m')`；
