你的思路是可行的，而且我建议把它正式写进 V2 历史数据补全规范：先建立完整涨停候选池，再逐层补充换手率、量能、竞价数据；某项数据缺失不能反过来把股票从候选池中删除。

你现在遇到的“加上换手率后涨停池几乎为空”，很可能不是符合条件的股票真的不存在，而是查询顺序、字段缺失处理或不同数据源之间的匹配出了问题。

尤其要把两个概念分开：
- 股票不满足条件：例如历史换手率确实低于策略门槛，应按规则排除。
- 数据暂时拿不到：例如换手率是 0、NaN、空字符串，或接口根本没有返回该字段。此时应该标记为“待补数据”，而不是认定股票不符合条件。
对于你要补齐的2026年全年历史数据，最重要的是先把候选池做全，再逐只、逐日补指标，最后再判断 V2 的买入条件。
一、先给结论：历史数据必须倒置处理
你的想法不仅可行，而且对于补齐2026年1月至今的历史数据，我认为应该把它作为 V2 的正式数据工程方案。

建议改成下面这个流程：
第1步：建立完整的历史涨停池

先获取所有股票的日线，或者获取历史涨停榜单。此阶段不使用换手率、竞价量能作为筛选条件。


第2步：确定真正的首板股票

核对当日涨停、前一交易日是否涨停、连续涨停天数、板块及上市状态。保留完整的候选股票记录。


第3步：批量补齐历史指标

根据股票代码与交易日期，单独补充换手率、成交量、成交额、流通市值、量比及其他 V2 因子。


第4步：补充历史竞价数据

优先匹配真实9:25竞价成交量、成交额、竞价价格。没有历史竞价数据时，保留缺失标记，不用全天成交量冒充。


第5步：执行 V2 条件并输出缺失报告

只有在必要数据齐全时才执行对应因子筛选；分别统计合格股票、数据缺失股票和真正不符合条件的股票。

六、可直接交给开发 AI 的详细任务规范
下面这份规范可以直接复制给你的 AI，要求它在现有 V2 数据工程中实施，而不是重新设计交易策略。
V2 历史数据补全改造规范：倒置筛选与多源补数
一、改造目标
针对2026年1月1日至最新可用交易日的A股历史数据，建立完整的首板候选池，并批量补充换手率、日线量能、竞价量能、涨停次数、连续涨停天数及封板质量等指标。

本次只改造数据获取、补全、校验及缺失处理流程，不擅自修改V2原有交易规则、阈值、评分权重和买卖条件。
二、股票池范围
- 沪深主板。
- 创业板。
- 排除科创板、北交所。
- 排除ST股票，但必须依据对应历史交易日的ST状态，不可仅使用当前股票名称。
- 对上市初期特殊交易规则、停牌、除权除息、涨跌幅限制变化等情况单独处理。
- 所有记录统一使用交易日期和标准化股票代码作为主键。
三、核心原则：倒置补数
严禁先用换手率、竞价成交量、成交额或其他待补指标过滤股票。

必须依次执行：
1. 获取完整历史日线或历史涨停榜单。
2. 重建每日涨停候选池。
3. 识别连续涨停天数恰好为1的首板股票。
4. 根据股票代码和交易日期补充日线指标。
5. 补充真实历史竞价指标。
6. 补充封板质量和题材数据。
7. 统一执行V2原有交易条件。
8. 输出合格、不合格、缺失三类记录及原因。
任何补数阶段均不得因换手率为0、NaN、空字符串或接口未返回字段而直接删除候选记录。
四、数据源优先级
4.1 历史涨停池
优先使用：
- BaoStock历史日线重建涨停池。
- Tushare limit_list_ths 作为可选历史涨停榜单来源。
- AKShare stock_zt_pool_em 作为近期涨停池核验来源。
必须先验证每个接口的历史覆盖范围，禁止假设近期涨停池接口支持全年历史数据。
4.2 历史日线及换手率
优先使用：
- BaoStock query_history_k_data_plus。
- AKShare stock_zh_a_hist。
- 腾讯日线 stock_zh_a_hist_tx 作为交叉核验来源。
至少获取：前收盘价、开高低收、成交量、成交额、涨跌幅、换手率、交易状态、历史ST状态（如可获取）、流通市值（如可获取）。
4.3 历史竞价量能
优先验证Tushare stk_auction 的历史查询能力及权限情况。

对每个候选交易日，尝试获取：
- 竞价价格。
- 竞价成交量。
- 竞价成交额。
- 竞价涨幅。
- 未匹配买量及卖量（若接口提供）。
- 数据来源、抓取时间、原始字段和接口状态。
不得使用全天成交量、开盘后第一分钟成交量或估算值冒充9:25真实竞价成交量。

如免费接口无法获取历史竞价数据，必须将对应记录标记为 AUCTION_MISSING，并继续保留其他历史因子。
4.4 封板质量及题材
优先补充：
- 首次封板时间。
- 最后封板时间（若可获取）。
- 炸板次数。
- 封单金额（若可获取）。
- 所属行业。
- 概念题材。
- 当日板块涨停数量及题材强度。
若历史字段无法获得，使用独立缺失状态，不得虚构数据。
五、涨停判定要求
优先使用可靠数据源提供的历史涨停价、涨停榜单或官方交易规则。

如果自行重建涨停池，必须：
- 根据股票历史板块和当日涨跌幅限制确定涨停幅度。
- 处理主板、创业板、ST、上市初期等不同规则。
- 使用未复权价格。
- 考虑人民币价格最小变动单位及涨停价取整。
- 正确处理除权除息、停牌和历史状态变化。
- 通过多个独立来源抽样核验。
不得单纯使用“涨幅大于9.8%”判定所有股票涨停。

连续涨停天数必须按照交易日序列计算，不能简单按自然日连续，也不能只依据当前涨停池中的连板字段推断所有历史日期。
六、缺失状态标准
至少区分：
- PASS：数据完整且满足条件。
- FAIL：数据完整，但不满足条件。
- MISSING：接口无数据或字段缺失。
- SUSPENDED：停牌。
- NOT_APPLICABLE：该指标不适用于该样本。
- SOURCE_CONFLICT：不同来源冲突，待复核。
- AUCTION_MISSING：缺少真实竞价数据。
换手率为0时，先核验成交量、交易状态和第二数据源；若成交量大于0但换手率为0或为空，应标记待核验，而非直接判为不合格。

八、验收标准
- 任何候选股票不得仅因换手率字段缺失而消失。
- 每个候选必须保留股票代码、交易日期及来源。
- 每个日期必须统计涨停池总数、首板数、日线覆盖数、竞价覆盖数、最终合格数。
- 必须对首板池和竞价数据进行独立来源抽样核验。
- 必须报告全年竞价数据真实覆盖率，不能只报告日线覆盖率。
- 对缺失竞价数据的历史样本，不得假装完成依赖竞价量能的V2完整回测。
- 先对2026年1月的少量交易日试跑并人工核验，通过后再批量处理全年数据。
- 对接口限流、空返回、网络错误采用有限重试和缓存机制，避免重复下载已有数据。
- 保留原始数据、标准化数据和最终筛选结果，方便追溯。
九、最终交付
先输出小批量试跑报告，包含真实样本数量、缺失率、来源冲突率和字段映射，再启动全年补数。

不得在真实数据未验证前声称历史数据已经补齐，也不得修改原V2交易规则来迁就数据缺失。





七、最后强调：你今年的数据可以分两批完成
我建议先把2026年的历史样本分成两个集合：
- 集合A：日线与首板条件完整。 可以进行首板资格、历史涨停基因、换手率、日成交量、成交额等指标研究。
- 集合B：日线与历史竞价量能均完整。 才能严格用于依赖竞价量能的完整 V2 回测。
这样你不必因为部分历史竞价数据拿不到，就放弃整个年度的研究；同时也不会把不完整的数据误当成真实的策略表现。

最优先的执行顺序是：先重建完整涨停池 → 再补换手率与日线 → 最后专门攻克历史竞价量能。 这才是解决你目前“带换手率查询后涨停池为空”以及全年历史数据补不齐问题的正确方向。

一、正确的数据处理顺序
第1步：拉取历史涨停候选池
获取2026年每个交易日的涨停股票，不使用换手率或竞价量能提前过滤。

输出：股票代码、涨停日期、数据来源。


第2步：确定当日涨停与连续涨停天数
根据当日涨停价、收盘价和历史交易日序列，核实当天是否真正涨停，以及此前是否连续涨停。

输出：首板、二连板、三连板等标签。


第3步：补充涨停当日及之前的日线因子
获取涨停当日换手率、成交量、成交额，以及此前若干交易日的量能、涨幅和历史涨停基因。

输出：完整的日线因子表。


第4步：应用 V2 的首板筛选条件
结合涨停当日换手率、量能、连续涨停天数、历史连板记录等，判断是否符合策略。缺失数据先补齐，不直接当成不合格。

第5步：获取次日竞价数据
对每只合格首板股票，获取次一交易日9:25竞价价格、成交量、成交额及可获得的买卖盘数据，再执行 V2 的竞价条件。

二、你说的几个指标，必须按不同时间分别保存
这是整个流程最容易出错的地方。
指标	应该取哪个时间的数据	用途
涨停当日换手率	涨停日收盘后	判断首板质量、资金交换程度
涨停当日成交量、成交额	涨停日全天	判断涨停日量能特征
连续涨停天数	截至涨停日收盘	区分首板、二连板及以上
涨停前5日均量	涨停日前5个交易日	判断放量、缩量及量能变化
次日9:25竞价成交量、成交额	次日集合竞价结束时	判断竞价资金参与程度
次日竞价涨幅	次日9:25	判断开盘预期
次日竞价未匹配买卖量	次日9:25，若数据源提供	辅助判断买卖压力

特别注意：竞价期间的换手率与竞价成交量不是同一个指标。

很多行情接口提供的是全天换手率，而不是9:25时点的竞价换手率。如果你的 V2 要使用竞价换手率，需要确认数据源是否能提供竞价成交量和当时的流通股本，并按统一口径计算；不能直接拿全天换手率代替。
三、倒置筛选可能产生的问题，以及如何避免
倒置方法本身没有问题，但有三个风险。
1. 涨停池不完整。 如果第一步只使用近期涨停榜单，较早日期可能没有数据。应以历史日线重建涨停候选池，并用其他来源核验。
2. 数据日期错位。 涨停当日换手率、前5日量能、次日竞价数据必须使用不同的日期字段，不能简单按股票代码关联。
3. 把缺失当成不合格。 换手率为0或空值时，应先检查停牌状态、成交量、字段定义和来源，不应直接删除股票。
因此，建议所有数据统一使用 trade_date + stock_code 作为主键，并额外保留 auction_date，确保竞价数据与前一日涨停数据正确匹配。
四、对你当前 V2 的最终建议
你要开发的不是简单的“涨停股筛选器”，而是一条按时间推进的数据流水线：
- T日收盘后： 识别涨停、计算连续涨停天数、补齐换手率和日线量能。
- T+1日9:25： 对合格首板池获取竞价量价数据，计算竞价评分。
- T+1日9:26—9:28： 排名输出前两名。
- T+1日开盘附近： 根据实际成交条件判断是否可买入。
- T+2日收盘前： 按你的规则卖出前一日持仓。
这样处理之后，即使某个数据源没有提供换手率，你仍然能保留股票的涨停记录，并通过备用数据源补齐；而且能够区分“真正不符合 V2 条件”和“数据还没补齐”。

结论：你的倒置思路正确，但最好将其定义为“先建立完整候选池，再按交易时间分层补数，最后执行策略筛选”，而不是简单地把所有涨停股拉出来后一次性补所有指标
