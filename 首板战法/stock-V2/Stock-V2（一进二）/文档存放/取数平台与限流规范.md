## 0. 铁律（全局）

1. **禁止绕开门禁**：业务代码不得直接狂打接口；一律 `platform_slot("平台名")` 或经共享门面。  
2. **软上限停跑（底层最高优先级）**：实际可用 = `floor(硬上限 × soft_cap_pct)`；**任一平台到软上限 → 立即终止当日该回补任务**，游标保留，等**下一个作业窗**再开跑。禁止顶满硬上限、禁止换号硬撞。  
   - **tdx / mootdx / pytdx** → **70%**  
   - **其余平台** → **80%**  
3. **同平台同时仅 1 个在途请求**；遵守 `min_interval_sec`。  
4. **观测 429 / 封禁 / 空连异常**：`mark_rate_limited(平台)`，当日（或当夜）停该平台。  
5. **作业总窗（固定）**：**当日 10:00 → 次日 02:00**。V2 历史全部补完前，**不启动 V1 买卖价回补**；V2 完工后再用同一总窗补 V1。总窗只是调度边界，**不能突破软上限**。  
6. **缺真数不得造假**：尤其 9:25 竞价量额；标 `MISSING` / `AUCTION_MISSING` / `DATA_UNAVAILABLE`。  
7. **改限额只改 JSON**，禁止在业务脚本写死更大数字。  
8. **新平台准入**：必须先调研（官方/社区配额、实测 QPS、封禁特征）→ 写入 `platform_rate_limits.json`（含 `soft_cap_pct` / 间隔 / 日或夜上限）→ 再写业务调用。**禁止盲目拍限额、禁止未登记就打量。**

## 2. 时间窗

| 窗口 | 时段 | 允许平台 / 任务 | 说明 |
|------|------|-----------------|------|
| **作业总窗（铁律）** | **10:00 → 次日 02:00** | V2 优先；V2 全部完成后再 V1 | 到点收工；**软上限随时可提前收工** |
| V2 真竞价（tdx） | 现行代码 **11:00–14:30**（落在总窗内） | **tdx** | 小时满可等整点；**日软满 → 当日停** |
| Stage A/B 名单与换手 | 总窗内非早盘安静段 | ths / eastmoney / tencent | 池与换手；不占 tdx |
| V1 买卖价（仅 V2 完工后） | 同总窗 | sohu / tencent / sina | 原夜班逻辑迁入总窗调度 |
| 安静 | 05:00–09:30；及总窗外 | — | 护早盘通知 |
| 早盘 live | 09:24–09:29 | 腾讯快照等 | **不占 tdx 历史配额** |

人工补跑：可设 `IGNORE_WINDOW=1` + `WAIT_HOUR_RESET=1`（**仍守日/时软上限**；日满必须停到次日总窗）。

### 相对补全规范的「新增可用」（本仓已落地、规范原文未列为生产主源）

1. **同花顺涨停池（ths）** — 历史日能出代码名单；换手常 0 → 交 Stage B。  
2. **通达信/mootdx 09:25 分笔（tdx）** — 已实测可取历史竞价量价；是当前 V2 回补真竞价主源（不是 Tushare）。  
3. **搜狐开盘估价（sohu）** — 看板买价 / `BACKFILL_OPEN` 估价，不占 tdx。  
4. **磁盘涨停池缓存** — `zt_pool_cache/{YYYYMMDD}.json`，命中不耗配额。

## 4. 按 V2 倒置流水线选平台

```

Stage C-开盘估价     →  sohu / tencent   （无真量时标 BACKFILL_OPEN，不冒充量额）
卖价                 →  sina / tencent
```

## 6. 升格全局时的要求（预告）

升格后本文迁入 `00_项目必读/` 或 `01_量化模型/共享取数/`，并满足：

- 所有模型（V1 主板/创业板、V2、涨停回头、新模式）**同一 JSON + 同一 gate**  
- 新平台必须先**调研再登记限额**再写业务代码（见 §0.8）  
- CI/手工验收：故意打满软上限应抛停，不得静默超限  
- 调度统一服从 **10:00–02:00 总窗** + **软上限当日终止**  

在升格完成前，**以本文件 + `platform_rate_limits.json` 为双权威**；冲突时以 JSON 数字为准，本文说明流程。
