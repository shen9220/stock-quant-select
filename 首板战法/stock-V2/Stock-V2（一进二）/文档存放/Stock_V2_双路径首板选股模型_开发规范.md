# Stock V2.0 双路径首板选股模型——开发实施规范

> 文档版本：V2.2（全量评审建议合并版） / 2026-10-28  
> 状态：待开发、待历史回测验证  
> 适用：沪深主板与创业板；排除科创板、北交所、ST及风险警示股  
> 基线：`stock/stock.py` 现有 Stock V1，V1 保持可运行，不得直接覆盖  
> 核心目标：在 D0 真首板池中，D1 9:25 完成可交易候选排序；主路径 A 寻求自然换手后的次日晋级，辅助路径 B 寻求低开/平开的日内修复；优先控制大幅亏损、不可成交与异动风险，不承诺每日盈利 5%。

## 0. 开发执行原则（必须遵守）

1. **硬过滤先于评分**；被剔除的股票不得因为高分重新入选。最终推荐数量为 **0–2**，不强行凑数。
2. **A/B 独立评分、独立回测、独立门槛**；不得直接比较未校准的 A 路 85 分和 B 路 85 分。统一输出可解释的最终优先级与路径标签。
3. **绝不使用未来数据**：D0 因子只使用 D0 收盘前已知数据；D1 9:25 因子只使用 9:25 已形成的竞价结果；9:30 后数据不得回填到 9:25 排名。
4. **不得假造数据**：关键竞价字段、首板身份、异动风险或封板细节缺失时，明确 `DATA_UNAVAILABLE` / `REVIEW_REQUIRED`，默认不推荐。
5. **不以次日一定涨停为前提**；收益率目标 3%–5% 是研究及退出策略参数，不是每日收益保证。必须检验尾部损失、跳空和跌停无法卖出的风险。
6. 任何阈值标注 `USER_POLICY`、`EXCHANGE_RULE` 或 `RESEARCH_HYPOTHESIS`，禁止把研究阈值写成交易所法规。

7. **历史涨停池 / 买卖价 / 竞价取数**必须走跨模型共用规范与门面，禁止再单独只调东财 `stock_zt_pool_em`：  
   - 规范：`01_量化模型/共享取数/历史涨停池与买卖竞价取数规范.md`  
   - 门面：`01_量化模型/共享取数/lib/hist_market_data.py`  
   - 流水线倒置：先名单 → 再补换手 → 再竞价/开盘估价；缺换手标 `REVIEW_REQUIRED`，不得因换手字段空而判「整日涨停池为空」。



## 1. 交易日与执行时间


| 标记  | 定义        | 用途                                |
| --- | --------- | --------------------------------- |
| D-1 | D0 的前一交易日 | 真首板身份校验                           |
| D0  | 前一交易日涨停日  | 首板质量、历史涨停、趋势、异动历史                 |
| D1  | 计划买入日     | 9:25 竞价决策；9:30 开始真实成交检验           |
| D2  | D1 下一交易日  | 退出日，保留 09:35 卖点，午盘修改13:35 卖点作基准对照 |


- D0 收盘后：缓存全量行情、首板和炸板数据，冻结 D0 特征。
- D1 08:50：运行预筛、检查数据覆盖率，输出初选池；**不得把预筛结果当作最终买入推荐**。
- D1 09:25–09:28：采集最终集合竞价数据、重新评分、风控、输出 Top0–2；留足 UI 同步时间。
- D1 09:30：记录实际可成交价格、成交数量、滑点和未成交原因。开盘成交不等于保证按开盘价成交。
- D1 09:30–09:32：可选 `CONFIRM_MODE` 承接确认，必须与 `OPEN_MODE` 分开回测，禁止拿确认后的信号回填开盘成交价。
- D2：执行预先声明的卖出规则；触及跌停但不能成交时按真实约束继续记录，禁止虚拟按跌停价完成卖出。



## 2. 股票池与统一硬过滤



### 2.1 基础候选池

- D0 必须真实收于对应涨停价，且出现在经核验的涨停池；核验前收盘价、复权/除权状态和适用涨跌幅限制。
- D-1 不得涨停；如果 D-1 涨停池为空或接口异常，必须交叉验证日线涨停状态；不能把空接口当成零涨停。
- 允许沪深主板 `600/601/603/605/000/001/002/003` 与创业板 `300/301`，代码白名单与证券主数据联动，防止漏掉新增前缀。
- 排除科创板、北交所、ST/*ST、退市整理、停牌、无正常涨跌幅限制的特殊交易日、上市初期无法可比样本等。



### 2.1.1 D-1 前一交易日核验：必须实现的独立闸门（P0）

**禁止只做** `D0涨停池 - D-1涨停池` **后直接认定真首板。** 必须先计算官方交易日历上的 `D-1 = previous_trading_day(D0)`，并核验证券在 D-1 的真实交易状态；对 D0 每个候选执行以下校验：

1. 获取 D-1 涨停池及其 `trade_date`、来源、抓取时间、完整性标志、数量；`HTTP 200`、空列表或缓存命中**均不代表**数据有效。
2. 用 D-1 未复权日线收盘价、前收盘价、适用涨停价、涨停状态以及停牌/特殊交易日信息**独立交叉核验**；不能只根据 D-1 涨幅是否恰好为10%/20%判断涨停（价格最小变动单位及规则差异）。
3. 若 D-1 已涨停，无论 D0 涨停池是否出现该票，均剔除 `REJECT_NOT_FIRST_BOARD`；若 D-1 非涨停且 D0 确认涨停，才允许进入下一层。
4. 若 D-1 涨停池为空，但日线能核实**全部候选**的 D-1 状态，可以按逐股核验结果继续；不能把“空池”当作“全市场零涨停”。若两路数据冲突，进入 `DATA_CONFLICT`，不推荐该股；如果全池数据质量无法确认，整次任务 `NO_TRADE`。
5. D-1 停牌、缺交易记录、无涨跌幅限制、上市初期、复牌特殊日等情况，不得自动当作“上一交易日未涨停”，应按交易所规则明确处理；无法可靠判定则 `REVIEW_REQUIRED`。
6. 保存审计字段 `d_minus_1_date`, `d_minus_1_limitup_pool_status`, `d_minus_1_daily_limitup_verified`, `d_minus_1_daily_source`, `d_minus_1_check_status`, `d_minus_1_reject_reason`。
7. D-1 是**前一个交易日**，不是日历昨天；周一应正确处理上周五，节假日应正确跨越休市日。D0、D-1 及历史窗口都必须使用同一交易日历版本。

**单元测试**：正常真首板；D-1涨停的二连板；D-1接口空但日线证实涨停；D-1接口失败；D-1接口与日线冲突；周末/长假；停牌复牌；除权除息；D0数据时间错位。以上异常不得误放入Top2。

### 2.1.2 首板判定扩展：不得漏掉的边界（P0）

- 证券代码按交易所、证券类型和有效期识别，不仅依赖固定前缀；退市、风险警示、特殊涨跌幅限制及新股无涨跌幅限制日必须剔除。
- D0收盘确实封住涨停，和盘中曾触板但收盘未封住是不同状态；炸板池不能直接混入涨停池。
- 若涨停池与日线记录冲突，保留原始响应及时间戳，明确拒绝原因，不得自动猜测修正。
- 为历史三连板检查，须额外向窗口起点之前回溯至少2个有效交易日，识别**跨越30日窗口边界**的连续涨停；窗口内存在连续3板时必须过滤，边界外完全结束的连板按30日规则处理。



### 2.2 历史连板风险（P0，绝对排除）

**规则 H01**：以 D0 为截止，向前回看 **30 个完整交易日（包含 D0）**，只要出现任何一次 **连续涨停天数 >=3**，即 `REJECT_RECENT_3PLUS_STREAK`。即使中间断板后 D0 再次首板，也必须排除。统计连续性必须按交易日，不按自然日。

- 示例：某股 D0 前 20、21、23 号对应的连续交易日曾形成三连板，随后断板，27 号再首板，28 号不得推荐。日期本身是否构成连续交易日必须按交易所日历计算。
- 同时保存 `max_consecutive_limitups_30td`、`last_3plus_streak_end_date`、`days_since_3plus_streak`。
- 近30日累计涨停次数仅用于风险分析，不再按次数线性加分；频繁涨停但未触发三连板者仍需接受异动和累计涨幅过滤。
- 历史数据不足30个完整交易日且不能可靠补全：`REVIEW_REQUIRED`，不进入自动 Top2。



### 2.3 首板形态过滤（P0）


| 编号  | 规则                   | 初始参数/条件                        | 动作          |
| --- | -------------------- | ------------------------------ | ----------- |
| H02 | D0 首板换手过低            | `<5%`                          | 剔除          |
| H03 | D0 首板换手过高            | `>20%`                         | 剔除          |
| H04 | D0 成交量/前5个交易日均量过低    | `<1.2`                         | 剔除          |
| H05 | D0 成交量/前5个交易日均量过高    | `>4.0`                         | 默认剔除（待回测确认） |
| H06 | D0 一字板或不可自然交易的极度缩量秒板 | 以逐笔/分钟成交及开板记录识别                | 剔除          |
| H07 | D0 首次有效封板晚于14:30     | `first_seal_time >14:30`       | 剔除          |
| H08 | 烂板且回封弱               | 炸板次数 `>=3` 且回封成交/封单弱，或最后封板接近尾盘 | 剔除          |
| H09 | D1 竞价高开过度            | `auction_gap >6%`              | A/B 均剔除     |
| H10 | D1 涨停一字且无现实买入机会      | 无可执行成交机会                       | 剔除/未成交      |


**注意**：`>=3` 次炸板并不等于必然烂板；必须结合回封质量。若回封成交、封单变化不可取得，则保守处理为待复核，不可编造“回封弱”。D0 的 5 日均量使用 **D0 之前5个完整交易日** 的成交量均值，不能把 D0 自己算进基准。

**阈值性质**：H02–H10 是用户偏好及研究初始规则，非交易所规定；保留配置化与消融测试。尤其 H05 `>4.0` 和 H08 的量化细则需用样本验证，避免误杀真正的强势换手板。

## 3. 异动与累计涨幅双重风控（P0）



### 3.1 法规核对：不能把“30天100%”当统一交易所标准

按已核验交易所官方资料，常见**严重异常波动**包括：

- **连续10个交易日**日收盘价格涨跌幅**偏离值**累计达到 **+100%**（负向为 -50%）；
- **连续30个交易日**日收盘价格涨跌幅**偏离值**累计达到 **+200%**（负向为 -70%）；
- 10个交易日内多次同向异常波动：主板一般为4次，创业板为3次；另有交易所认定的其他情形。

“偏离值”不是简单涨停次数 ×10%/20%，也不是自然月涨幅。需要按对应交易所、板块、基准指数、窗口、除权除息与已公告重置机制计算。普通异常波动还有主板/创业板各自的3日偏离标准。**达到严重异动披露标准不等于法律自动规定次日必然停牌或跌停**。

参考：

- 上交所《上海证券交易所交易规则（2026年修订）》：[https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml](https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml)
- 深交所《主板股票交易机制》：[https://investor.szse.cn/institute/rules/t20230803_602428.html](https://investor.szse.cn/institute/rules/t20230803_602428.html)
- 深交所《股票竞价交易严重异常波动》：[https://www.szse.cn/www/investor/index/update/t20230621_601277.html](https://www.szse.cn/www/investor/index/update/t20230621_601277.html)

**开发要求**：在实现前再次核验运行日有效交易规则；以交易所正式规则为准，不以论坛、行情软件俗称“异动100%”替代。

### 3.2 用户自定义累计涨幅上限（独立于法规）

用户希望避免短期累计暴涨后 D1 买入、D2 卖出期间出现风险。V2 建立两层风控：

1. `EXCHANGE_RISK`：精确计算近3/10/30交易日异常及严重异常波动指标，包含D1/D2最坏上行涨停情景的**预警压力测试**。需要记录当前规则口径与是否已经公告重置；未来指数不可知时采用保守情景而不是伪造确定值。
2. `USER_PRICE_RUNUP_CAP`：用户自定的 **30交易日累计股价涨幅 90%** 保护阈值（**不是交易所法定阈值**），以 D0 为基准，预测 D1 和 D2 各自涨停价情景；任一情景超过上限则不推荐。该90%为最终硬上限，不再额外扣减缓冲；达到或超过90%即剔除。

建议计算：

```
P_base = D0之前第29个交易日收盘价  # 与D0组成30个收盘观察点；需明确窗口口径
P_D0 = D0收盘价
P_D1_limit = 按D1真实涨跌幅限制、最小报价单位及规则计算的涨停价
P_D2_limit_scenario = 以P_D1_limit为前收盘价，计算D2情景涨停价
runup_D1 = P_D1_limit / P_base - 1
runup_D2 = P_D2_limit_scenario / P_base - 1
reject if max(runup_D1,runup_D2) >= USER_PRICE_RUNUP_CAP
```

- 上述为**滚动30个收盘观察点的简单累计价格涨幅**，不是“逐日涨幅相加”。除权除息应使用可比价格序列；涨停价用实际未复权价格与交易所报价规则。
- 另行计算过去10/30交易日的 **相对基准指数涨幅偏离** 与公告重置状态，不得用上述 `runup` 代替。
- D1/D2 情景仅用于提前排除“接近上限”股票；不意味着预测两天一定涨停。
- **P0默认**：异动历史数据、指数基准、复权或重置状态无法可靠确认时，不做自动推荐。



### 3.3 历史高位与加速风险补充

即使未达30交易日90%自定义上限，仍记录 `runup_5td`、`runup_10td`、`runup_20td`、`distance_to_20td_high`、`limitup_count_30td`、`max_streak_30td`；用于排查快速加速、短期高位、密集涨停后再启动的形态。暂不引入无证据的“必跌”判断。

## 4. A/B 双路径信号与硬边界



### 4.1 路径 A：自然首板后的次日晋级

- D1 竞价高开 **+2% 至 +6%**，边界包含 +2%、+6%。
- 核心研究子区间 **+3% 至 +6%**；`+2%~+3%` 单独分层统计，不自动等同黄金区间。
- D0 首板换手优选 **7%–15%**，基础健康区间 **6%–18%**；竞价换手优选 **0.8%–1.5%**，观察区间 **0.6%–1.5%**。
- 竞价成交额 / D0 全日成交额建议 `>=5%` 才有资格评分，**10%–20%** 为优选研究区间；高于20%不自动判强。
- 不追 D1 高开 >6%、一字板、极度缩量秒板或明显缺乏可执行买入机会。
- 路径 A 的目标是晋级概率与**可成交后净收益**兼顾，不要求一定二板。



### 4.2 路径 B：低开/平开后的日内修复

- D1 竞价开盘区间 **-5% 至 +2%**，重点分档 `[-5%,-3%)[-3%,-2%)`、`[-2%,-1%)`、`[-1%,0%)`、`[0%,1%)`、`[1%,2%)`。
- `-5%` 以下默认不进入自动推荐（允许仅研究记录）；低开不因为价格便宜而自动高分。
- D0 首板质量必须更严格：首板换手优选 `7%–15%`，量比 `1.5–3.0`，首次封板不晚于10:30，炸板次数与回封结构健康。
- 竞价换手 `>=0.8%` 才允许负开候选自动入选；`0%~+2%` 可允许 `>=0.6%` 进入评分但降权。
- 竞价成交额/D0成交额 `>=5%`，优选10%–20%；竞价弱且低开时直接不推荐。
- B 路只以**修复概率、可实现净收益与回撤**评价，不预设二板；默认研究 2%–3% 的基准兑现和 3%–5% 的扩展兑现两套规则。
- `-3%~0%` 的买入信号不保证当日拉红；必须单独统计高点触及率与真实成交率。



### 4.3 路径重叠和决策

- +2% 恰好处于 A/B 边界：默认只归 A，避免重复推荐；B 定义为 `[-5%,+2%)`。
- 每只股票同时计算全局硬过滤和唯一的路径评分。
- 每路径可以推荐0–2只，但**最终全市场总计最多2只**；不同路径的原始分不直接混排，使用经样本外校准的预期净收益/下行风险指标比较；校准未完成时采用可配置的A优先策略，B仅在达到更严格门槛时补位，UI标注“未校准”。
- 同行业/同题材的两只票需要标注相关性；允许设置组合集中度限制，不能把相关性当成独立收益来源。



## 5. 100分制评分——路径 A

> 所有子分项必须有明确0至上限的裁剪。下表给出分值、推荐映射方向与研究区间；具体连续评分函数通过分段线性插值实现，边界点可配置。对同源量能指标必须做相关性与消融检验，防止重复计分。


| 组         | 二级因子             | 满分      | 初始评分逻辑                                       |
| --------- | ---------------- | ------- | -------------------------------------------- |
| A1 竞价承接   | D1竞价换手率          | 20      | 0.8%–1.5%满分；0.6%–0.8%递增；<0.3%为弱竞价并剔除；>1.5%递减 |

## 7. 分段评分实现与数据缺失

推荐通用函数 `piecewise_score(x, knots, cap)`，相邻节点线性插值，区间端点明确，最终 `clip(score,0,cap)`。示例（非最终回测参数）：

```python
# 路径A竞价换手：单位是百分数数值，如 1.0 表示 1%
auction_turnover_knots = [
    (0.30, 0), (0.60, 8), (0.80, 20),
    (1.50, 20), (2.00, 10), (3.00, 0)
]
# 路径A高开：3%~5%最高，6%以上进入硬过滤
auction_gap_knots = [
    (2.0, 10), (3.0, 20), (5.0, 20), (6.0, 8)
]
```

- D0 首板换手、D0量比、竞价额占比也使用梯形或分段线性评分；不能直接 `成交额 × 常数` 或 `换手 × 常数` 无限加分。
- 竞价换手率分母必须使用**D1可流通股数**，竞价成交量为实际集合竞价撮合成交股数；竞价额占比的分母是 D0 全日**成交额**，严禁成交量/成交额混用。
- `auction_volume_vs_20d` 使用同一证券过去20个有效交易日的9:25最终竞价成交量均值；历史样本不足时按可核验规则剔除/待复核，不得用全日量替代。
- 数据质量等级：`VERIFIED`、`PARTIAL`、`MISSING`、`STALE`；核心字段非 `VERIFIED` 不进入自动推荐。
- 题材缺失时可选 `STRICT_MODE` 全部拒绝，或 `RESEARCH_MODE` 显示不完整评分；**生产默认STRICT_MODE**。



## 8. 二板盘中量能因子：只做观察，不可进入9:25评分

用户提出的二板相对首板量能60%–100%、换手60%–100%、10:30前封板等，**在D1收盘或盘中才知道**，属于未来观察/持仓管理，不得用于D1 9:25的模型排名。


| D1观察项         | 研究参考                    | 用途             |
| ------------- | ----------------------- | -------------- |
| D1全日量/D0全日量   | 60%–100%；缩量30%–50%为候选假设 | D1收盘后归因、预测D2风险 |
| D1全日换手/D0全日换手 | 60%–100%；绝对换手>25%警惕     | 持仓复盘/次日退出研究    |
| D1首次有效封板时间    | 10:30前为研究偏好             | 持仓管理及二板质量记录    |


不能在9:25使用这些指标，也不能以“二板最终封住”筛掉实际当天买入后炸板的历史样本，否则发生幸存者偏差。

## 9. 开盘承接确认（可选独立模式）

- `OPEN_MODE`：9:25信号，9:30起按可执行成交规则下单/模拟；不得依赖9:30后的任何指标。
- `CONFIRM_MODE`：9:30–9:32确认，参考开盘价是否失守、前2分钟成交与价格回撤、买卖盘持续性；确认后按实际可成交价格买入。
- 不能把 `CONFIRM_MODE` 的更高胜率和 `OPEN_MODE` 的更好开盘买价拼接成一个虚假策略。
- 先把 `CONFIRM_MODE` 做为影子实验，不默认影响主路径 A/B 的9:25推荐。



## 10. 推荐决策与风控

1. **硬过滤**：真首板、近30交易日三连板、异常/累计涨幅压力测试、首板换手/量比、封板形态、D1竞价缺失、高开>6%、可成交性。
2. **路径分流**：`[2%,6%]` → A；`[-3%,2%)` → B；其他不推荐。
3. **各自100分**：生成逐因子得分、数据时间戳、剔除原因与总分。
4. **初始建议最低分**：A `>=75`，B `>=82`（均为待回测参数，不是已验证阈值）；分数不足则空缺。
5. **最多两只**：优先选择独立校准后预期净收益更高且下行风险更小的候选；校准前默认A优先、B更高准入门槛，并在UI明确标注。
6. **集中度控制**：同题材双票可以配置为只留一只；如第二只与第一只高度同质，可只推一只。
7. **风控开关**：当市场环境、近期策略回撤或关键数据源异常时允许全日 `NO_TRADE`。
8. **强制解释**：每个候选记录“为何入选、为何未入选、风险点、9:25快照、预期路径”；禁止只输出总分。



## 11. 收益目标与退出规则

- 用户期望日内约5%利润，但模型**不能保证每日5%**；区分 `D1盘中最高浮盈`、`D1可成交卖出收益`、`D2实际卖出净收益`。
- A股股票买入后一般受T+1约束：**D1买入不能D1卖出**。因此“路径B当日修复3%–5%兑现”只可作为盘中触及统计，**不能作为D1实际卖出策略**；必须在D2或之后按照可执行规则卖出。若用户持有底仓并使用不同交易策略，需单独定义，不得默认。
- 退出基准 `EXIT_BASELINE`：D2 09:35或13:15，分别回测，不使用事后最优卖点。
- 退出候选 `EXIT_V2`：D2条件止盈、时间退出、风险退出；所有价格触发都需成交模拟，涨跌停无法卖出要计入尾部风险。
- 明确计算：`net_return = (actual_sell_price - actual_buy_price)/actual_buy_price - fees - taxes - slippage`；考虑买卖双方实际费率和最低收费。
- 对“D1涨停、D2跌停”的情景做专项压力测试；D2跌停无法卖出时延长持仓与亏损统计，不可假设当日必定卖出。

## 13. 回测研究设计与防止虚假胜率

**用户提供的以下数据暂属未经本项目复核的研究假设**：首板换手6%–18%正溢价率>70%；竞价换手0.8%–1.5%封板率47.9%；高开3%–6%+竞价换手0.8%–1.5%封板率59.4%；烂板次日低开概率84.1%；竞价额占比10%–20%优选等。不得在报告中宣称已被本模型验证。

必须完成：

1. 尽可能覆盖多个市场阶段、至少跨年度的完整历史样本；按时间滚动训练/验证/测试，保留严格样本外区间。
2. 先对**全体D0真首板**建立样本，再执行过滤，记录每项过滤的样本数、误杀机会、后续收益与风险；不能只回测最终Top2。
3. 统计 A 路竞价开盘分档：`2%–3%`、`3%–4%`、`4%–5%`、`5%–6%`；与竞价换手 `[0.3,0.6)`、`[0.6,0.8)`、`[0.8,1.0)`、`[1.0,1.5]`、`>1.5` 交叉分层。
4. B 路分档：`[-2,-1)`、`[-1,0)`、`[0,1)`、`[1,2)`；统计D1盘中最大涨幅、D1收盘表现、D2可执行净收益、D2跌停不可卖比例；不得将D1触及+5%当成可兑现收益。
5. 分析 D0 换手 `[5,6)`、`[6,10)`、`[10,15)`、`[15,18]`、`(18,20]`；D0量比 `[1.2,1.5)`、`[1.5,2)`、`[2,3]`、`(3,4]`。
6. 分析三连板过滤、30日累计涨幅过滤、10日偏离值风险、首板炸板过滤的单独效果和组合效果；报告样本量、胜率、均值、中位数、分位亏损、最大回撤、净收益。
7. 严格处理开盘买不到、涨停排队、跌停卖不掉、滑点、印花税、佣金、交易所费用、停牌、除权除息、幸存者偏差、退市股与时间穿越。
8. 对照 V1、V2-A、V2-B、V2混合，以及移除单个因子的消融版本；衡量风险调整后收益，而非只优化封板率。
9. 统计策略推荐0/1/2只的天数、实际可成交率、每笔持有期、最大单笔亏损、5%目标触及率与实际可实现率。
10. 报告每个比例的分母、日期范围、置信区间、样本数；不足样本不得声称“稳定胜率”。

### 13.2 D0预筛、D1竞价、D2退出的数据防穿越协议

- **D-1/D0收盘快照**：记录`feature_asof=D0 15:00`、数据发布时间、缓存抓取时间；晚于D0才发布的公告/行业标签不得伪装成D0已知。
- **D1竞价快照**：记录`feature_asof=D1 09:25`、供应商时间戳、接收时间、字段口径；只接受9:25最终撮合已形成的数据。9:26以后抓取但内容为9:25快照可以使用，须核验未混入连续竞价成交。
- **D1盘中及D2成交**：只用于执行或事后归因，不能修改已冻结的9:25推荐分数。历史回测同样执行。
- **同源字段相关性**：成交额、量、换手、竞价额比可能高度相关，输出相关系数与移除单因子的效果；未证明增益时避免重复奖励。
- **分板块比较**：各板块按自身分布计算百分位/稳健标准化，最终用独立样本校准净收益和尾部风险；不可仅用两边百分位相等就宣称风险相同。

## 15. 用户已确认的4项产品决策（开发硬约束）


| 参数                              | 已确认取值                 | 实现要求                                                                                |
| ------------------------------- | --------------------- | ----------------------------------------------------------------------------------- |
| `USER_PRICE_RUNUP_CAP`          | **90%**（0.90）         | 以30个交易日观察窗口计算简单累计价格涨幅，分别对D1、D2涨停情景压力测试；任一 `>=0.90` 直接剔除。该阈值为用户风控，并非法定异动线。           |
| `HISTORICAL_STREAK_LOOKBACK_TD` | **30个交易日**            | 截止D0（含D0），任意历史连续涨停 `>=3` 直接剔除；交易日历必须正确。                                             |
| `PATH_B_MIN_AUCTION_GAP`        | **-3%**               | B路区间 `[-3%, +2%)`；小于-3%直接剔除。`[-3%,-2%)` 只在竞价承接和D0首板质量均满足B路严格门槛时进入评分，不能因为低开较深而获得更高分。 |
| `RECOMMENDATION_ALLOCATION`     | **A优先，B补位，最多2只，允许空仓** | A、B独立评分和门槛；先选合格A路候选，再以合格B路填剩余席位。不得强制每条路径各出1只，也不得凑满2只。                               |


**配置示例（所有百分比单位统一明确）：**

```yaml
stock_v2:
  user_price_runup_cap_ratio: 0.90
  historical_streak_lookback_trading_days: 30
  historical_streak_reject_at: 3
  path_a_gap_pct_min: 2.0
  path_a_gap_pct_max: 6.0
  path_b_gap_pct_min: -3.0
  path_b_gap_pct_max_exclusive: 2.0
  allocation: A_FIRST_B_FILL
  max_recommendations: 2
  allow_no_trade: true
```

**边界测试必须覆盖**：累计涨幅89.99%允许继续检查、90.00%拒绝；B路-3.00%可入池、-3.01%拒绝；+2.00%仅归A；A不足两只时B补位；A/B都不合格时输出0只。

**实盘限制**：参数确认仅代表开发规范可定稿，不代表策略已经回测合格或授权自动下单；仍须完成数据校验、样本外回测与人工上线验收。

## 16. 实施顺序

**阶段一（P0）**：保留V1 → 建立D-1双路核验的真首板与历史三连板过滤 → 法规/自定义涨幅风控 → 数据质量与as-of快照 → 测试。  
**阶段二（P0）**：核验9:25竞价接口 → A/B双路径评分 → 0–2只推荐 → JSON/MD/UI输出。  
**阶段三（P1）**：历史全池回测、交易成本、不可成交模拟、样本外检验 → 校准阈值。  
**阶段四（P1）**：连续观察与影子运行 → 对照V1 → 经人工确认后再决定是否启用真实交易。  
**阶段五（P2）**：9:30–9:32独立承接确认模式、市场环境动态阈值、策略监控。

**完成定义**：不是“每天一定推荐2只”或“每天赚5%”，而是可复现、无未来函数、能识别高位风险、能解释空仓、真实可成交、并在样本外评估中有明确风险收益表现的双路径首板模型。
